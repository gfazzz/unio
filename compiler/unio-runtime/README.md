# unio-runtime

The runtime of Unio 0.1, following [docs/runtime.md](../../docs/runtime.md): the value model,
faults and termination, the release stack of `using`, and the 70 external functions that the
standard library in `stdlib/` declares. It is the first half of sprint S5; the interpreter that
evaluates programs on top of it is the second. Rust stable and the standard library only.

```sh
cd compiler
cargo test -p unio-runtime
cargo clippy -p unio-runtime --all-targets -- -D warnings
```

## What is here

| Module | Contents |
|---|---|
| `value.rs` | `Value`: `Int`, `Float`, `Bool`, `Text`, `Bytes`, `Path`, lists, tuples, maps, sets, structs and errors, enums (with `Option` and `Result`), function values, resources. `Text` keeps an index of character positions, so `length`, `slice`, and `char_at` are constant time and a slice shares storage. Maps and sets iterate in insertion order and hash with FNV-1a, so a program prints the same on every run. |
| `heap.rs` | `Counted`: every heap object of a value adds its size to a per-thread total when created and subtracts it when dropped; `Runtime::check_heap` turns a total above the heap limit into code 102. Sizes are capacity estimates. |
| `fault.rs` | `Unwind` (error, fault, exhaustion), `Fault` with kind, message, and trace, exit codes 101, 102, and 103, `main_exit_code`, `Int` arithmetic with its faults, and `ReleaseStack`, which runs releases in reverse order on normal exit and errors and keeps going after a failing release while a fault unwinds. |
| `runtime.rs` | `Runtime`: program arguments, standard output and error (captured in tests), the call stack for traces with its depth limit, the heap limit, the descriptor table, resource identities, and the fault-injection hook `fail_point` of requirement S-9b. |
| `externs/` | The external functions, grouped by layer: `core.rs`, `alloc.rs`, `float_text.rs`, `system.rs`, `files.rs` with `durability.rs`, `process.rs`. |

### Memory without a cycle collector

Values never share mutable state and function values capture copies, so a value can never reach
itself. Reference counting therefore frees every value, and `Rc::make_mut` gives copy-on-write:
a shared value is copied at the level that changes, an unshared one is changed in place
(L-11b). This meets C-13 for the interpreter; the native runtime of S6 decides after measuring.

## The binding table

`unio_runtime::bindings()` maps the full name of every external to a Rust function
`fn(&mut Runtime, &mut [Value]) -> Outcome`:

- a method in `extend T:` is `T.name`, for example `Text.slice`, `List.append`;
- a function of `prelude.unio` or a `builtin/` file is its bare name: `assert_fail`, `Path`;
- any other function is `std.module.name`: `std.files.system_rename`, `std.process.run`.

The interpreter passes every argument, defaults included, and `self` first. A `var self`
method changes `arguments[0]` in place; the interpreter stores it back into its place.
`tests/bindings.rs` scans `stdlib/` and fails when a declaration has no binding or a binding has
no declaration.

Notes on particular externals:

- `std.json.to_value` and `std.json.from_value` are generated by the compiler for each type
  (S-5); the runtime bindings fault with kind `NotProvided`.
- `Float.to_text` writes the shortest text that reads back: decimal notation with a fractional
  part for exponents −6 to 20 (`2.0`, `0.1`), otherwise `1e+300`; non-finite values are `nan`,
  `inf`, `-inf` and do not read back through `Text.to_float`, which accepts only decimal and
  scientific notation.
- `Text.index_of` faults for a start outside `0..length()`, like `slice`.
- `std.files.rename` never replaces a target: a file is linked under the new name (which fails
  atomically if it exists) and then unlinked; a directory, or a file system without links, is
  checked and then renamed, with a short window for a race. On Windows it is `MoveFileExW`
  without `MOVEFILE_REPLACE_EXISTING`, which is atomic.
- The commit primitives: `system_sync_data` is `File::sync_all` (fsync on Linux, `F_FULLFSYNC`
  on Apple platforms, `FlushFileBuffers` on Windows); `system_close` removes the descriptor from
  the table before reporting the result of closing, so it is never closed twice;
  `system_rename` is `rename` or `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING |
  MOVEFILE_WRITE_THROUGH`; `system_sync_directory` fsyncs the directory (falling back from
  `F_FULLFSYNC` to `fsync` on Apple platforms) and does nothing on Windows.
- `system_supports_durability` reads `/proc/self/mountinfo` on Linux, `statfs` on Apple
  platforms, and `GetVolumeInformationW` on Windows, and accepts ext4, XFS, Btrfs, APFS, NTFS.
- `std.env.home_dir` asks `getpwuid` on Unix; on Windows it uses the profile directory that
  `std::env::home_dir` reports.
- `std.process.run` starts the program without a shell, with empty standard input; a program
  ended by a signal has status 128 plus the signal; `timeout_seconds` must be positive.

## What the interpreter of S5 must add

- Lowering the checked syntax tree to an IR with resolved names, local slots, error edges, and
  release points, and evaluating it in the order of docs/runtime.md section 1.
- Function values: an implementation of `Callable` for named functions and closures that capture
  values.
- Calling externals through the binding table, storing `var self` results back, and building
  `IoError`, `ProcessError`, `ReadStep`, `TemporaryFile`, and `Output` values that match the
  declarations (this crate builds them by field name in declaration order).
- `using` through `ReleaseStack`, faults with traces through `Runtime::enter`, `leave`, and
  `at_line`, and the exit codes of `main`.
- `unio run` and `unio test` with isolated test blocks and T-5a, and the JSON conversions of
  `std.json`.
