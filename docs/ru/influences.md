# Что Unio берёт из других языков, а что отклоняет

Версия: 0.4. Изменения относительно 0.3: Zero (Vercel Labs), сравнение по вопросу читателя. Изменения относительно 0.2: краткость по образцу Ruby и Python, RFC 0002. Изменения относительно 0.1: RFC 0001 и точные контракты кеша. Статус: решения внесены в `docs/ru/concept.md` 0.14 и `docs/ru/requirements.md` 0.13. Английская версия (основная): `docs/influences.md`. Документ хранит обоснования в одном месте, чтобы те же предложения не обсуждались заново.

Проверка для каждого заимствования — принцип концепции: понятный код, явное поведение, контролируемые ресурсы. Возможность берётся, только если она усиливает читаемость, явность, проверяемость до выполнения или удобство для ИИ. Мощная возможность, дающая второй способ записать то же самое, отклоняется.

## 1. Zig

| Идея | Решение | Где |
|---|---|---|
| Ошибки как значения с пробросом `try` и набором ошибок в сигнатуре | Уже есть. `try` пробрасывает, `fails with` — контракт, вызов без обработки не компилируется, правило одинаково в любой позиции. Легче делать не нужно: убрать `try` значит скрыть поток управления. | концепция 3.2 |
| Нет скрытого потока управления | Уже есть: нет исключений, неявных преобразований, деструкторов за спиной читателя; `release` выполняется только в конце блока `using`, который виден. | концепция 1, 4.1 |
| Явная передача аллокатора | Принято только для профиля `system`. В `system` каждая функция слоя `alloc` принимает `Allocator` первым параметром, а аллокатор — `Resource` с жизнью в `using`. В `application` единственный аллокатор — куча GC, параметра нет: прикладной код не должен платить читаемостью за потребность, которой у него нет. | концепция 8.1 |
| `comptime` | Отклонён для 0.1 и не планируется как блок. Параметры обобщений и константы `let` из литеральных выражений — единственное вычисление на этапе компиляции. Общий `comptime` — второй способ выполнять код, его трудно читать без выполнения, и он нарушает требование SB-14: компилятор никогда не выполняет пользовательский код. Если появится потребность (размеры аппаратных таблиц, таблицы поиска), она предлагается как RFC с чистым, завершающимся подмножеством в песочнице. | ТЗ SB-14 |

## 2. Odin

| Идея | Решение | Где |
|---|---|---|
| Явный параметр `Context` | Отклонён. Unio уже передаёт то, что нёс бы контекст, видимыми средствами: аллокатор явным параметром в `system`, полномочия через манифест и выведенные эффекты, журналирование через `std.log` с передаваемым журналом там, где нужно. Неявный параметр контекста в каждом вызове — скрытое состояние. | концепция 6, 8.1 |
| Ортогональность, один способ | Уже есть и обеспечивается: процесс RFC требует раздел «почему существующих конструкций недостаточно», форматтер приводит к одной стандартной форме. Метрика проекта «размер словаря» это отслеживает. | rfcs/README.md, план 7 |

## 3. Gleam

| Идея | Решение | Где |
|---|---|---|
| Диагностика, понятная с первого прочтения | Принято и сделано требованием. Каждое сообщение об ошибке следует одному шаблону: что не так, где и как исправить, с исправлением в виде патча там, где оно есть. Сообщение не может называть внутренности компилятора (имена проходов, внутренние типы, виды узлов). Каждый новый код диагностики проверяется по шаблону и на корпусе Н-10 до слияния. | ТЗ Н-12 |
| Один стиль и форматтер без настроек | Уже есть: `unio fmt` без настроек, идемпотентен. | ТЗ И-1 |

## 4. Mojo

| Идея | Решение | Где |
|---|---|---|
| Постепенное раскрытие сложности | Принято как документированный путь, а не новый механизм. Слои уже дают его: писать в `application` с GC; переносить горячую или чувствительную к памяти часть в код, проверяемый `--profile=core`, или позднее в профиль `system` с явным аллокатором. Руководство описывает этот путь одним примером, который спускается по слоям и показывает, что каждый шаг стоит и даёт. | концепция 8.1, ТЗ Д-2 |
| Сначала высокоуровневый API, затем буферы и backend | Принято для выпуска 0.3 «Вычисления»: API тензоров проектируется сначала для обычного пользователя, а управление буферами, размещением и backend — явный нижний слой того же API, а не отдельный. | концепция 8, план 8 |

## 5. Unison

| Идея | Решение | Где |
|---|---|---|
| Адресация кода по содержимому | Принято как возможность инструментов, а не семантика языка. `unio symbol` сообщает хеш содержимого для каждой функции и типа: хеш нормализованного объявления и тела вместе с хешами всего, на что они ссылаются. Хеш входит в составные ключи кеша сборки и тестов (К-11b) и позволяет ИИ-агенту назвать точную версию функции. В исходном коде остаются обычные имена; ничто в языке от хешей не зависит. | ТЗ К-11a |

## 6. Отклонено сознательно

| Возможность | Почему |
|---|---|
| Владение и заимствование в стиле Rust | GC и `Resource` покрывают память и внешние ресурсы; единственный анализ владения в Unio — проверка, что ресурс не покидает свой блок `using`, и он остаётся таким же маленьким. Времена жизни в сигнатурах стоили бы той читаемости, ради которой язык существует. |
| Макросы и тяжёлая метапрограммная система | Второй способ записать всё, код, который нельзя прочитать без раскрытия, и нарушение SB-14. |
| C-interop «из коробки» | FFI для пользовательского кода вне 0.1; `external function` есть только в стандартной библиотеке и в файлах `unsafe module` профиля `system`. |
| Классы и наследование реализации | Отклонены с самого начала: структуры, интерфейсы и композиция. |

## 7. Принятые находки расширенного обзора

Python: обязательные имена и ключи сортировки; Ruby: небольшой полный API коллекций; JS/TS: владение задачами и проверка внешних данных; Swift/Rust: исключительность доступа и согласованность реализаций; Go/Unison: точная семантика, зависимости и кеш; C#/Kotlin/Java/OTP: итерация, отмена и надзор. Принято в [RFC 0001](rfcs/0001-language-contracts.md), [контрактах](language-contracts.md), ТЗ Я-27–Я-32, К-11b, Б-13–Б-20, И-12–И-15 и плане §11. Концепция 0.13, ТЗ 0.12. Прежние отклонения сохраняются; поздние возможности явно привязаны к релизам.

## 8. Ruby и Python: краткость

| Идея | Решение | Где |
|---|---|---|
| Блоки Ruby и короткие анонимные функции | Принято в форме Unio: анонимная функция сохраняет `function`, а её типы берутся из ожидаемого типа функции. Второй синтаксис анонимных функций (`{ \|x\| ... }`, `=>`) отклонён. | RFC 0002, Я-8a |
| Тело в одну строку (`if x: return y` в Python) | Принято только для веток, и форму выбирает форматтер, поэтому у каждой ветки одна форма записи. | RFC 0002, И-1a |
| `case ... in` из Ruby 3 и `if let` из Rust | Принято как `expr is pattern` с именами, связанными в охраняемой ветке; `match` остаётся способом обработать несколько вариантов. | RFC 0002, Я-33 |
| Неявный `return`, необязательные скобки, `unless`, `until`, модификаторы инструкций | Отклонено: несколько форм записи одного смысла и поток управления, который легко пропустить при проверке. | концепция 1, обоснование 20 |
| `name: Text` вместо `name as Text` | Не предлагается: выигрыш меньше цены изменения всех исходников и документов. | RFC 0002, альтернативы |

## 9. Swift и Python: подсчёт ссылок

| Идея | Решение | Где |
|---|---|---|
| Автоматический подсчёт ссылок вместо трассирующего сборщика | Принято для интерпретатора S5. Значения никогда не делят изменяемое состояние, а замыкания захватывают копии, поэтому ни одно значение не может ссылаться само на себя, и подсчёт ссылок освобождает всё без сборщика циклов; он же сообщает копированию при изменении, разделено ли значение, и не даёт пауз сборки. Сохранит ли нативная среда выполнения его вместо трассирующего сборщика К-13, решают измерения S6, а изменение К-13 требует RFC. | runtime.md 3, К-13 |

## 10. Zero

Zero (Zerolang, Vercel Labs, v0.3.4, Apache-2.0) это экспериментальный язык, который тоже проектируется под ИИ-агентов. Сравнение сделано по его README (github.com/vercel-labs/zerolang) после вопроса читателя; ничего сверх этой страницы из его компилятора и документации не взято.

| Идея | Решение | Где |
|---|---|---|
| Программа это семантический граф: компилятор читает `zero.graph`, текстовые файлы `.0` служат проекциями для людей, а агенты правят граф через `zero query` и проверяемые операции `zero patch` | Отклонено. В Unio источник истины это текст: программа пишется для читателя, который не её автор, и проверяется обычными средствами (diff, pull request). То, что граф даёт агенту, Unio даёт выводом инструментов поверх текста: `unio outline` показывает устройство файла, `unio symbol` сигнатуру, эффекты, вызовы, места использования и хеш содержимого, а диагностики в JSON несут исправления в виде патчей. | концепция 1, 7; К-11, К-11a |
| Правка, сделанная по устаревшему хешу графа, отклоняется до записи | Частично есть: `unio symbol` даёт каждому объявлению хеш содержимого по его телу и всему, на что оно ссылается, так что агент может назвать точную версию, которую прочитал. Отказа в правке с устаревшим исходным хешем в 0.1 нет; если он понадобится, это задача инструментов (команды патча, которая проверяет хеш К-11a), а не языка. | К-11a |
| Возможности передаются значением (`main(world: World)`, `world.out.write(...)`) | Отклонено в такой форме. Unio объявляет полномочия один раз в манифесте, выводит эффекты каждой функции из её вызовов, запрещает использовать стандартную библиотеку сверх манифеста и исполняет манифест песочницей операционной системы. Параметр-возможность у каждой функции, которая обращается к системе, нагляден, но повторяет манифест в каждой сигнатуре; по той же причине отклонён `Context` из Odin. | концепция 6; раздел 2 |
| Инструкции для агентов поставляются с компилятором и соответствуют его версии (`zero skills`) | В Unio тот же материал лежит в `docs/ru/ai.md`: форматы JSON, рекомендуемый цикл и запросы. Поставлять его вместе с инструментами в версии, соответствующей компилятору, это кандидат для инструментов, а не принятое решение. | docs/ru/ai.md |
