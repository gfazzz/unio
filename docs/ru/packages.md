# Пакеты и зависимости

Версия: 0.1 (черновик). Английская версия (основная): [docs/packages.md](../packages.md). Документ описывает менеджер пакетов инструмента `unio` в том виде, в каком он реализован: манифест, файл блокировки, команды, кэш, конфигурацию оператора, подписанный реестр в виде статических файлов с его ключами и публикацией и формат архива. Нормативные требования — И-6–И-9 и И-14 из [requirements.md](requirements.md) с разделами 5 и 6 [language-contracts.md](language-contracts.md), а для изоляции работы — SB-10–SB-15; рабочие процессы описаны в [runtime.md](runtime.md) 9.7. Чего нет, перечислено в конце и в [status.md](status.md).

## 1. Манифест

Пакет — каталог с `unio.toml` (Я-22). Менеджер пакетов читает три таблицы:

```toml
[package]
name = "app"                 # строчные буквы, цифры, '-' и '_'
version = "0.1.0"            # семантическая версия; обязательна для пакета, от которого зависят другие
unsafe_modules = ["raw"]     # модули с пометкой `unsafe module` (И-6)

[dependencies]
util = { path = "../util" }
json = { registry = "main", package = "acme/json", version = "^1.2" }
vendored = { archive = "vendor/vendored-1.0.0.tar", sha384 = "<96 шестнадцатеричных цифр>" }

[permissions]
files.read = ["$CWD/**"]
```

Ключ зависимости — её псевдоним, имя в `import deps.<псевдоним>.<модуль>` (И-14): строчные буквы, цифры и `_`, не `std` и не `deps`. У зависимости ровно один источник:

- `path`: каталог относительно манифеста, который его называет. Его может использовать только корневой пакет и другие зависимости-каталоги.
- `registry` и `package`: пакет `владелец/имя` реестра с требованием `version`. Реестр называется именем, которое ему дал оператор (раздел 5); без `registry` корневой пакет использует реестр с именем `default`, а пакет реестра — свой реестр.
- `archive` и `sha384`: файл архива (относительно манифеста) или URL `http://` на хосте настроенного реестра с SHA-384 его байтов.

`version` — требование: `^1.2.3` (по умолчанию для голой версии), `~1.2`, `=1.2.3`, `>=1.0, <2.0`, `*`. Предварительная версия выбирается только тогда, когда требование называет предварительную версию той же версии. Табличная форма `[dependencies.util]` с `path = "../util"` под ней значит то же, что встроенная.

## 2. Идентичность, разрешение и блокировка

Идентичность пакета — его происхождение (И-14): `registry+<URL реестра>#<владелец>/<имя>`, `path+<каталог относительно корневого пакета>` или `archive+<файл относительно корневого пакета или URL>`. Два происхождения с одним именем — два пакета: их модули и типы различны, даже если файлы одинаковы. Выпуск 0.1 допускает одну версию на идентичность.

Разрешение (`unio add`, `remove`, `update`) — детерминированный перебор с возвратами по идентичностям в отсортированном порядке, который пробует версии, удовлетворяющие всем требованиям, по убыванию семантической версии. Зафиксированный пакет, не входящий в запрошенное обновление, сохраняет зафиксированную версию, и реестр о нём не спрашивают. Когда ни одна версия не подходит, ошибка называет каждый путь, требующий пакет (`the root package -> acme/b 1.0.0 requires ^1`), а для сохранённой версии предлагает `unio update <псевдоним>`. Две скрытые копии одного пакета не создаются никогда.

`unio.lock` перечисляет каждый пакет, прямой и транзитивный, с точной версией, хешем содержимого его файлов, SHA-384 его архива, адресами архива и подписи, ключом, чья подпись архива проверена (`signer`), хешем и порядковым номером индекса реестра, из которого выбрана версия (`index`, `index_sequence`; раздел 7.3), тем, что показал просмотр И-9, и его собственными зависимостями в виде `псевдоним|требование|идентичность`. Пакеты и все списки отсортированы, поэтому одно и то же разрешение даёт одни и те же байты; формат версионируется полем `lock_version` (2; версия 1, без `signer` и `index_sequence`, по-прежнему читается). Блокировку фиксируют в репозитории вместе с пакетом.

Хеш содержимого — SHA-384 версионированной канонической формы файлов (`unio-package-content-v1`: каждый файл в байтовом порядке имён, с длиной в рамке). Он называет запись пакета в кэше и связывает блокировку с теми файлами, которые просматривались. Сам по себе он ничего не удостоверяет ([cryptography.md](cryptography.md)).

## 3. Команды

| Команда | Что делает |
|---|---|
| `unio add ALIAS [VERSION] --path DIR` | добавляет зависимость-каталог, разрешает, устанавливает и записывает `unio.toml` и `unio.lock` |
| `unio add ALIAS VERSION --package OWNER/NAME [--registry NAME]` | то же для пакета реестра |
| `unio add ALIAS --archive FILE\|URL --sha384 HEX` | то же для архива с известным хешем |
| `unio remove ALIAS` | удаляет зависимость и пакеты, которые больше никому не нужны, из блокировки |
| `unio update [ALIAS...]` | разрешает заново, позволяя названным зависимостям (или всем) измениться |
| `unio install` | устанавливает в кэш ровно пакеты `unio.lock`; никогда не разрешает и не меняет блокировку |
| `unio publish --registry DIR --owner OWNER --key KEY` | публикует пакет рабочего каталога в каталог реестра с подписью (раздел 7.4) |
| `unio key new NAME [--dir DIR]`, `key id FILE` | создаёт пару ключей ML-DSA-65 вне любого пакета; печатает идентичность файла ключа |
| `unio key endorse PUBLIC --key SIGNER --registry DIR [--expires DATE]`, `key revoke PUBLIC\|ID --key ANCHOR --registry DIR` | ручается за ключ подписи или отзывает его в файлах доверия реестра |
| `unio registry init DIR --anchor ANCHOR`, `registry resign DIR --key KEY` | создаёт новый реестр; заново подписывает каждый архив и индекс после отзыва ключа |

Команды от `add` до `install` принимают `--offline` (без загрузки: пакет, которого нет в кэше и которому нужна сеть, — ошибка), `--unsafe-ok` (подтверждение И-9, раздел 6), а также `--policy FILE` и `--allow-weaker-sandbox` для своих рабочих процессов, как и другие команды. Команды ищут `unio.toml` в рабочем каталоге и выше. Ничего не записывается, пока всё не загружено, не проверено и не подтверждено: неудачная или отклонённая команда оставляет `unio.toml`, `unio.lock` и кэш как были. Зависимость-каталог копируется в кэш: после изменения её файлов выполните `unio update <псевдоним>`; `unio install` сообщает об изменении, а не фиксирует его молча.

`unio install` сначала проверяет, что блокировка соответствует манифесту (те же псевдонимы, идентичности и требования, и каждая зафиксированная версия удовлетворяет требованиям к ней); иначе останавливается и предлагает `unio update`. Пакет, который уже в кэше, он перечитывает в рабочем процессе и сверяет хеш содержимого.

`unio check`, `build`, `run`, `test` и языковой сервер читают только `unio.lock` и кэш и никогда не обращаются к сети (И-7): `import deps.util.strings` разрешается через блокировку корневого пакета в запись кэша `util`, а модуль зависимости так же импортирует модули своего пакета и своих зависимостей. Псевдоним, который не объявлен, объявлен, но не зафиксирован, или зафиксирован, но не установлен, — это E0048, и сообщение говорит, что именно и что выполнить.

## 4. Кэш

Кэш — это `UNIO_CACHE` или каталог кэша системы (`$XDG_CACHE_HOME/unio` или `~/.cache/unio` в Linux, `~/Library/Caches/unio` в macOS, `%LOCALAPPDATA%\unio\cache` в Windows). Запись — `packages/<шестнадцатеричный дайджест хеша содержимого>/` с файлами одного пакета. Записи создаются в `staging/` рабочим процессом распаковки и переименовываются на место инструментом, когда пакет проверен и подтверждён; после этого запись не меняется. Рабочим процессам компилятора разрешено читать только записи, которые называет блокировка их пакета (SB-11), а не весь кэш. `trust/state` в кэше хранит наибольшие порядковые номера подписанных файлов реестров, виденные на этой машине (раздел 7.3).

## 5. Конфигурация оператора

Реестры и пределы задаёт оператор, а не проект: `UNIO_PACKAGES_CONFIG` или `packages.toml` в каталоге конфигурации (`$XDG_CONFIG_HOME/unio` или `~/.config/unio` в Linux, `~/Library/Application Support/unio` в macOS, `%APPDATA%\unio` в Windows). Неизвестные ключи — ошибки.

```toml
[registry.main]
url = "http://registry.example.org/unio"
anchor = "keys/main.pub"    # якорь доверия реестра, относительно этого файла (раздел 7.2)

[limits]
archive_bytes = 67108864    # самый большой архив
unpacked_bytes = 67108864   # файлы одного пакета вместе
file_bytes = 16777216       # один файл
entries = 10000             # записи одного архива
depth = 32                  # каталоги в имени
```

Рабочий процесс загрузки может обращаться только к хостам настроенных реестров (SB-12): URL архива на другом хосте отклоняется до какой-либо загрузки, как и пакет, который нужно загрузить из реестра, не указанного в конфигурации. Каждому реестру нужен `anchor` — файл открытого ключа его якоря доверия, который оператор получает независимо от реестра (от его оператора, лично или по каналу, которому оператор доверяет); ключу, который называет только сам реестр, никогда не доверяют. Прежний `allow_unsigned`, устанавливавший пакеты реестра без проверки, отклоняется с сообщением: никакой параметр не принимает пакет реестра без действительной подписи ([cryptography.md](cryptography.md), раздел 3: никакое исключение не может разрешить установку пакета). Код без подписи по-прежнему можно использовать как зависимость-архив, `sha384` которой называет сам корневой манифест.

## 6. Просмотр И-9

Установка пакета, у которого есть модули с пометкой `unsafe module` (перечисленные в `unsafe_modules` или найденные разбором его модулей) или который объявляет полномочия, которых нет у корневого пакета, требует явного подтверждения. Для каждого такого пакета инструмент показывает помеченные модули; то, что в 0.1 они не содержат внешних функций (их отклоняет E0086) и не получают более широких полномочий (RFC 0004); и полномочия, которые он объявляет сверх полномочий корневого пакета. Модуль с пометкой, которого нет в списке, или модуль из списка без пометки — предупреждение. Подтверждение — `--unsafe-ok` или `yes`, набранное в терминале; без него ничего не меняется. `unio install` спрашивает о каждом таком пакете блокировки; `add` и `update` — о новых и изменившихся.

Подтверждение ничего не даёт. Полномочия зависимости никогда не расширяют полномочия корневого пакета: программа работает с полномочиями манифеста своего пакета, суженными политикой (SB-2), а `[permissions]` зависимости для песочницы не читается. Статически вызов из корневого пакета в зависимость несёт эффекты зависимости, поэтому их должен разрешать манифест корневого пакета (E0085), а модули зависимости проверяются по её собственному манифесту.

## 7. Подписанный реестр как статические файлы

Реестр — дерево каталогов, которое может раздавать любой статический HTTP-сервер. `unio registry init`, `unio key` и `unio publish` записывают его на машине публикующего; раздавать его или копировать на сервер — дело публикующего (сервиса загрузки нет):

```text
<реестр>/index/<владелец>/<имя>.json              индекс пакета
<реестр>/index/<владелец>/<имя>.json.sig          его конверт подписи
<реестр>/archives/<владелец>/<имя>/<версия>.tar   архив версии (раздел 8)
<реестр>/archives/<владелец>/<имя>/<версия>.tar.sig
<реестр>/trust/keys                               поручительства за ключи подписи
<реестр>/trust/revocations                        список отзыва, подписанный якорем
<реестр>/trust/anchor.pub                         открытый ключ якоря, только для справки
```

Индекс пакета:

```json
{
  "format": "unio-registry-index-2",
  "package": "acme/json",
  "sequence": 3,
  "versions": [
    {
      "version": "1.2.0",
      "archive": "archives/acme/json/1.2.0.tar",
      "sha384": "<96 шестнадцатеричных цифр архива>",
      "signature": "archives/acme/json/1.2.0.tar.sig",
      "dependencies": [{"alias": "text", "package": "acme/text", "version": "^1.0"}]
    }
  ]
}
```

`sequence` растёт с каждым изменением индекса. У каждой версии есть подпись; формат 1, где их не было, отклоняется. Пути относительны реестру и не могут выйти из него (`..`, абсолютные пути и другие хосты отклоняются); зависимости называют пакеты того же реестра. Манифест в архиве должен иметь имя и версию записи индекса и те же зависимости, иначе пакет отклоняется. Клиент отправляет `GET` с `Connection: close`, не следует перенаправлениям и ограничивает размер каждого ответа.

### 7.1 Подписи

Каждая подпись Unio — конверт из девяти строк ASCII ([cryptography.md](cryptography.md), раздел 7): формат `unio-envelope-1`, назначение, алгоритм `ml-dsa-65` и набор параметров `fips204-ml-dsa-65`, идентичность ключа (`sha384:` и SHA-384 его открытого ключа с префиксом области), предмет, порядковый номер, SHA-384 всей полезной нагрузки и подпись ML-DSA-65 (FIPS 204, чистый вариант с контекстом `unio-envelope-1`) восьми предыдущих строк. Другой алгоритм, набор параметров, формат или назначение отклоняется и никогда не проверяется иначе.

| Назначение | Полезная нагрузка | Предмет | Порядковый номер | Кто подписывает |
|---|---|---|---|---|
| `package-archive` | архив | `owner/name@version` | 0 | доверенный ключ |
| `registry-index` | документ индекса | `owner/name` | `sequence` индекса | доверенный ключ |
| `key-endorsement` | ключ, за который ручаются, и срок его действия | идентичность ключа | 0 | якорь или доверенный ключ |
| `revocations` | список отзыва | `registry` | номер списка | только якорь |
| `release-manifest` | манифест выпуска | выпуск | номер выпуска | ключ выпуска ([compiler/README.md](../../compiler/README.md)) |

### 7.2 Доверие

- **Якорь** — ключ из `anchor` в конфигурации оператора. Ничто из того, что раздаёт реестр, не может его заменить.
- **Поручительства** в `trust/keys` делают доверенными другие ключи: каждое называет открытый ключ и необязательную дату окончания (`expires 2027-06-30`, первый день, когда ему больше не доверяют, по UTC) и подписано якорем или ключом, которому доверяют сами, не более восьми поручительств от якоря. **Ротация** — поручительство за новый ключ старым ключом или якорем.
- **Список отзыва** в `trust/revocations` подписывает только якорь, и у него есть порядковый номер. Отозванному ключу не доверяют, как и ключу, за который поручились только через него, и всему, что они подписали. После ротации старым ключом якорь сам ручается за новый ключ, прежде чем отозвать старый.
- Файл доверия, подпись которого не сходится или который искажён, отклоняет всю установку.

### 7.3 Что проверяет установка

1. Инструмент загружает `trust/keys`, `trust/revocations` и конверт индекса как есть и не разбирает ни один из них.
2. Рабочий процесс загрузки проверяет файлы доверия по якорю и конверт индекса с наименьшим порядковым номером, который он может принять, *до* разбора индекса: доверенный ключ, назначение `registry-index`, предмет пакета, дайджест ровно загруженных байтов и порядковый номер не ниже нижней границы; `sequence` документа должен совпадать с подписанным.
3. Версия, которую записывает блокировка, должна остаться в индексе с тем же хешем архива: реестр, удаливший или заменивший опубликованную версию, отклоняется (И-8).
4. Рабочий процесс распаковки сверяет SHA-384 архива с индексом или блокировкой, затем его конверт (`package-archive`, `owner/name@version`, дайджест архива, доверенный ключ) и только потом читает архив.
5. `unio install` по блокировке делает то же для каждого загружаемого пакета: блокировка, изменённая так, чтобы называть другой архив, или пакет, ключ которого с тех пор отозван, отклоняется.

Защита от отката: нижние границы — наибольшие виденные порядковые номера каждого индекса и списка отзыва каждого реестра, хранимые в кэше (`trust/state`), и `index_sequence` в блокировке. Более старый индекс или список отзыва, подписан он правильно или нет, отклоняется. Отказ на любом шаге оставляет `unio.toml`, `unio.lock` и кэш как были. Блокировка записывает подписавший ключ и порядковый номер каждого пакета реестра. Пакеты, уже находящиеся в кэше, проверены при установке и сверяются с хешем содержимого.

### 7.4 Публикация и ключи

`unio key new NAME` создаёт пару ключей ML-DSA-65 из 32 байт системного источника случайности (если он отказал, ключ не создаётся): `NAME.key`, секретное зерно, доступное для чтения только владельцу (в Linux и macOS; в Windows файл получает права своего каталога), и `NAME.pub`. Каталог по умолчанию — `keys/` в каталоге конфигурации Unio; каталог внутри пакета отклоняется, чтобы ключ никогда не попал в репозиторий или публикацию, а существующий ключ никогда не перезаписывается. Зерно затирается нулями, когда инструмент с ним закончил. Подпись — детерминированный вариант FIPS 204, случайность ей не нужна.

`unio publish --registry DIR --owner OWNER --key KEY` публикует пакет рабочего каталога как `OWNER/<имя>`: создаёт архив по правилам зависимости-каталога (раздел 8; одни и те же файлы всегда дают одни и те же байты, а с детерминированной подписью — одну и ту же подпись), отклоняет пакет, который содержит файл секретного ключа или зависимость, не являющуюся пакетом того же реестра с требованием к версии, записывает архив и его конверт и добавляет версию в индекс со следующим порядковым номером и новым конвертом. Версия, уже опубликованная с тем же содержимым, ничего не меняет; с другим содержимым она отклоняется: опубликованная версия никогда не заменяется и не удаляется, и ни одна команда её не удаляет (И-8). Отзыва версий (yanking) в требованиях нет, и его нет.

Порядок действий оператора:

```sh
unio key new anchor --dir /media/offline        # якорь остаётся вне сети
unio registry init /srv/reg --anchor /media/offline/anchor.key
unio key new signer                              # в ~/.config/unio/keys/
unio key endorse ~/.config/unio/keys/signer.pub --key /media/offline/anchor.key --registry /srv/reg
cd mypackage && unio publish --registry /srv/reg --owner acme --key ~/.config/unio/keys/signer.key
```

Ротация: `unio key endorse new.pub --key signer.key` (или `--key anchor.key`), затем публикация новым ключом. Скомпрометированный ключ: `unio key revoke signer.pub --key anchor.key --registry /srv/reg`, поручительство якоря за замену и `unio registry resign /srv/reg --key replacement.key`, который сверяет каждый архив с его индексом и заново подписывает каждый архив и индекс со следующими порядковыми номерами. Клиенты передают открытый ключ якоря реестра (`trust/anchor.pub` — тот же файл, для справки) своим операторам по каналу, которому доверяют.

### 7.5 Транспорт

В 0.1 поддерживается только `http://` по решению от 2026-11-12: целостность, подлинность и защита от подмены и отката обеспечиваются подписями и подписанными порядковыми номерами выше, каков бы ни был транспорт. Чего транспорт не даёт, того нет: наблюдатель сети видит, какие пакеты и версии загружаются (нет конфиденциальности), а атакующий на пути может удерживать обновления или продолжать отдавать самый новый индекс, который клиент уже видел (нет свежести: у индексов нет подписанного времени). TLS появится с сетью версии 0.2, RFC которой определит профили ([cryptography.md](cryptography.md), раздел 5).

## 8. Формат архива

Архив пакета — несжатый архив POSIX ustar, какой делает `tar --format=ustar -cf pkg.tar -C pkg .`; файлы могут лежать и внутри одного каталога верхнего уровня. Это стандарт, который пишут существующие инструменты, его фиксированные 512-байтовые заголовки разбираются одной стандартной библиотекой Rust, а несжатый архив не может расшириться: каждый байт каждого файла присутствует в архиве, поэтому распакованный размер не превышает размера архива, который пределы ограничивают до чтения, и атаки через коэффициент распаковки нет. Сжатие спецификацией не требуется; сжатый формат был бы новой версией формата со своим пределом коэффициента.

Принимаются обычные файлы и каталоги с переносимыми относительными именами: буквы ASCII, цифры, `.`, `_`, `-`, `+`. Рабочий процесс распаковки отклоняет, до того как что-либо записано: абсолютные имена, `..`, обратные косые черты и другие символы, имена, которые Windows резервирует или не может сохранить (`CON`, `aux.unio`, точка в конце), символические и жёсткие ссылки, символьные и блочные устройства, FIFO, расширенные заголовки pax и длинные имена GNU, повторяющиеся имена, имена, различающиеся только регистром (они совпадают на файловых системах без учёта регистра, а пакет должен распаковываться везде одинаково), файл там, где нужен каталог, записей больше `entries`, имена глубже `depth`, файлы и пакеты сверх пределов размера, размер, выходящий за конец архива, неверную контрольную сумму заголовка и данные после конца архива. Файлы создаются заново, без битов исполнения и особых битов. Зависимость-каталог копируется по тем же правилам (ссылка в ней отклоняется), без имён, начинающихся с точки, и без `target/` и `unio.lock` в её корне.

## 9. Чего нет

- HTTPS, а с ним и конфиденциальности загрузок: 0.2 (раздел 7.5). Нет подписанного времени у индексов, поэтому удержание обновлений не обнаруживается.
- Независимого аудита безопасности, фаззинга разборщиков конвертов, файлов доверия и индексов (они строгие и ограниченные и проверены изменёнными и усечёнными входами) и проверки времени выполнения реализации ML-DSA: до тех пор ни один компонент не заявляет соответствие постквантовой политике (Н-6c; [cryptography.md](cryptography.md), раздел 7).
- Нескольких подписей на объект: порога из нескольких ключей нет; SLH-DSA как независимая альтернатива не выбран.
- Сервиса загрузки: реестр — это каталог, который его публикующий раздаёт или копирует.
- Требований к цели и среде выполнения в манифестах (раздел 6 language-contracts требует, чтобы установка их проверяла); манифесты 0.1 их не объявляют.
- Отзыва версий (yanking), которого требования не просят, и удаления старых записей кэша.
- В Windows у рабочих процессов пока нет ограничений файлов и сети (SB-4), поэтому рабочий процесс загрузки соединяется сам, а инструментам там нужна более слабая песочница ([runtime.md](runtime.md) 9.7).
