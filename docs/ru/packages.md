# Пакеты и зависимости

Версия: 0.1 (черновик). Английская версия (основная): [docs/packages.md](../packages.md). Документ описывает менеджер пакетов инструмента `unio` в том виде, в каком он реализован: манифест, файл блокировки, команды, кэш, конфигурацию оператора, статическую раскладку реестра и формат архива. Нормативные требования — И-6–И-9 и И-14 из [requirements.md](requirements.md) с разделами 5 и 6 [language-contracts.md](language-contracts.md), а для изоляции работы — SB-10–SB-15; рабочие процессы описаны в [runtime.md](runtime.md) 9.7. Чего нет, перечислено в конце и в [status.md](status.md).

## 1. Манифест

Пакет — каталог с `unio.toml` (Я-22). Менеджер пакетов читает три таблицы:

```toml
[package]
name = "app"                 # строчные буквы, цифры, '-' и '_'
version = "0.1.0"            # семантическая версия; обязательна для пакета, от которого зависят другие
unsafe_modules = ["raw"]     # модули с пометкой `unsafe module` (И-6)

[dependencies]
util = { path = "../util" }
json = { registry = "main", package = "acme/json", version = "^1.2" }
vendored = { archive = "vendor/vendored-1.0.0.tar", sha384 = "<96 шестнадцатеричных цифр>" }

[permissions]
files.read = ["$CWD/**"]
```

Ключ зависимости — её псевдоним, имя в `import deps.<псевдоним>.<модуль>` (И-14): строчные буквы, цифры и `_`, не `std` и не `deps`. У зависимости ровно один источник:

- `path`: каталог относительно манифеста, который его называет. Его может использовать только корневой пакет и другие зависимости-каталоги.
- `registry` и `package`: пакет `владелец/имя` реестра с требованием `version`. Реестр называется именем, которое ему дал оператор (раздел 5); без `registry` корневой пакет использует реестр с именем `default`, а пакет реестра — свой реестр.
- `archive` и `sha384`: файл архива (относительно манифеста) или URL `http://` на хосте настроенного реестра с SHA-384 его байтов.

`version` — требование: `^1.2.3` (по умолчанию для голой версии), `~1.2`, `=1.2.3`, `>=1.0, <2.0`, `*`. Предварительная версия выбирается только тогда, когда требование называет предварительную версию той же версии. Табличная форма `[dependencies.util]` с `path = "../util"` под ней значит то же, что встроенная.

## 2. Идентичность, разрешение и блокировка

Идентичность пакета — его происхождение (И-14): `registry+<URL реестра>#<владелец>/<имя>`, `path+<каталог относительно корневого пакета>` или `archive+<файл относительно корневого пакета или URL>`. Два происхождения с одним именем — два пакета: их модули и типы различны, даже если файлы одинаковы. Выпуск 0.1 допускает одну версию на идентичность.

Разрешение (`unio add`, `remove`, `update`) — детерминированный перебор с возвратами по идентичностям в отсортированном порядке, который пробует версии, удовлетворяющие всем требованиям, по убыванию семантической версии. Зафиксированный пакет, не входящий в запрошенное обновление, сохраняет зафиксированную версию, и реестр о нём не спрашивают. Когда ни одна версия не подходит, ошибка называет каждый путь, требующий пакет (`the root package -> acme/b 1.0.0 requires ^1`), а для сохранённой версии предлагает `unio update <псевдоним>`. Две скрытые копии одного пакета не создаются никогда.

`unio.lock` перечисляет каждый пакет, прямой и транзитивный, с точной версией, хешем содержимого его файлов, SHA-384 его архива, адресами архива и подписи, хешем индекса реестра, из которого выбрана версия, тем, что показал просмотр И-9, и его собственными зависимостями в виде `псевдоним|требование|идентичность`. Пакеты и все списки отсортированы, поэтому одно и то же разрешение даёт одни и те же байты; формат версионируется полем `lock_version`. Блокировку фиксируют в репозитории вместе с пакетом.

Хеш содержимого — SHA-384 версионированной канонической формы файлов (`unio-package-content-v1`: каждый файл в байтовом порядке имён, с длиной в рамке). Он называет запись пакета в кэше и связывает блокировку с теми файлами, которые просматривались. Сам по себе он ничего не удостоверяет ([cryptography.md](cryptography.md)).

## 3. Команды

| Команда | Что делает |
|---|---|
| `unio add ALIAS [VERSION] --path DIR` | добавляет зависимость-каталог, разрешает, устанавливает и записывает `unio.toml` и `unio.lock` |
| `unio add ALIAS VERSION --package OWNER/NAME [--registry NAME]` | то же для пакета реестра |
| `unio add ALIAS --archive FILE\|URL --sha384 HEX` | то же для архива с известным хешем |
| `unio remove ALIAS` | удаляет зависимость и пакеты, которые больше никому не нужны, из блокировки |
| `unio update [ALIAS...]` | разрешает заново, позволяя названным зависимостям (или всем) измениться |
| `unio install` | устанавливает в кэш ровно пакеты `unio.lock`; никогда не разрешает и не меняет блокировку |

Каждая команда принимает `--offline` (без загрузки: пакет, которого нет в кэше и которому нужна сеть, — ошибка), `--unsafe-ok` (подтверждение И-9, раздел 6), а также `--policy FILE` и `--allow-weaker-sandbox` для своих рабочих процессов, как и другие команды. Команды ищут `unio.toml` в рабочем каталоге и выше. Ничего не записывается, пока всё не загружено, не проверено и не подтверждено: неудачная или отклонённая команда оставляет `unio.toml`, `unio.lock` и кэш как были. Зависимость-каталог копируется в кэш: после изменения её файлов выполните `unio update <псевдоним>`; `unio install` сообщает об изменении, а не фиксирует его молча.

`unio install` сначала проверяет, что блокировка соответствует манифесту (те же псевдонимы, идентичности и требования, и каждая зафиксированная версия удовлетворяет требованиям к ней); иначе останавливается и предлагает `unio update`. Пакет, который уже в кэше, он перечитывает в рабочем процессе и сверяет хеш содержимого.

`unio check`, `build`, `run`, `test` и языковой сервер читают только `unio.lock` и кэш и никогда не обращаются к сети (И-7): `import deps.util.strings` разрешается через блокировку корневого пакета в запись кэша `util`, а модуль зависимости так же импортирует модули своего пакета и своих зависимостей. Псевдоним, который не объявлен, объявлен, но не зафиксирован, или зафиксирован, но не установлен, — это E0048, и сообщение говорит, что именно и что выполнить.

## 4. Кэш

Кэш — это `UNIO_CACHE` или каталог кэша системы (`$XDG_CACHE_HOME/unio` или `~/.cache/unio` в Linux, `~/Library/Caches/unio` в macOS, `%LOCALAPPDATA%\unio\cache` в Windows). Запись — `packages/<шестнадцатеричный дайджест хеша содержимого>/` с файлами одного пакета. Записи создаются в `staging/` рабочим процессом распаковки и переименовываются на место инструментом, когда пакет проверен и подтверждён; после этого запись не меняется. Рабочим процессам компилятора разрешено читать только записи, которые называет блокировка их пакета (SB-11), а не весь кэш.

## 5. Конфигурация оператора

Реестры и пределы задаёт оператор, а не проект: `UNIO_PACKAGES_CONFIG` или `packages.toml` в каталоге конфигурации (`$XDG_CONFIG_HOME/unio` или `~/.config/unio` в Linux, `~/Library/Application Support/unio` в macOS, `%APPDATA%\unio` в Windows). Неизвестные ключи — ошибки.

```toml
[registry.main]
url = "http://registry.example.org/unio"
allow_unsigned = false      # см. раздел 7

[limits]
archive_bytes = 67108864    # самый большой архив
unpacked_bytes = 67108864   # файлы одного пакета вместе
file_bytes = 16777216       # один файл
entries = 10000             # записи одного архива
depth = 32                  # каталоги в имени
```

Рабочий процесс загрузки может обращаться только к хостам настроенных реестров (SB-12): URL архива на другом хосте отклоняется до какой-либо загрузки, как и пакет, который нужно загрузить из реестра, не указанного в конфигурации.

## 6. Просмотр И-9

Установка пакета, у которого есть модули с пометкой `unsafe module` (перечисленные в `unsafe_modules` или найденные разбором его модулей) или который объявляет полномочия, которых нет у корневого пакета, требует явного подтверждения. Для каждого такого пакета инструмент показывает помеченные модули; то, что в 0.1 они не содержат внешних функций (их отклоняет E0086) и не получают более широких полномочий (RFC 0004); и полномочия, которые он объявляет сверх полномочий корневого пакета. Модуль с пометкой, которого нет в списке, или модуль из списка без пометки — предупреждение. Подтверждение — `--unsafe-ok` или `yes`, набранное в терминале; без него ничего не меняется. `unio install` спрашивает о каждом таком пакете блокировки; `add` и `update` — о новых и изменившихся.

Подтверждение ничего не даёт. Полномочия зависимости никогда не расширяют полномочия корневого пакета: программа работает с полномочиями манифеста своего пакета, суженными политикой (SB-2), а `[permissions]` зависимости для песочницы не читается. Статически вызов из корневого пакета в зависимость несёт эффекты зависимости, поэтому их должен разрешать манифест корневого пакета (E0085), а модули зависимости проверяются по её собственному манифесту.

## 7. Реестр как статические файлы

Реестр — дерево каталогов, которое может раздавать любой статический HTTP-сервер:

```text
<реестр>/index/<владелец>/<имя>.json
<реестр>/archives/<владелец>/<имя>/<версия>.tar
<реестр>/archives/<владелец>/<имя>/<версия>.tar.sig
```

Индекс пакета:

```json
{
  "format": "unio-registry-index-1",
  "package": "acme/json",
  "versions": [
    {
      "version": "1.2.0",
      "archive": "archives/acme/json/1.2.0.tar",
      "sha384": "<96 шестнадцатеричных цифр архива>",
      "signature": "archives/acme/json/1.2.0.tar.sig",
      "dependencies": [{"alias": "text", "package": "acme/text", "version": "^1.0"}]
    }
  ]
}
```

Пути относительны реестру и не могут выйти из него (`..`, абсолютные пути и другие хосты отклоняются); зависимости называют пакеты того же реестра. Манифест в архиве должен иметь имя и версию записи индекса и те же зависимости, иначе пакет отклоняется. Клиент отправляет `GET` с `Connection: close`, не следует перенаправлениям и ограничивает размер каждого ответа.

Подписи: рабочий процесс распаковки вызывает проверку подписи после того, как совпал хеш архива, и до того, как что-либо распаковано. Проверка ещё не реализована (И-8, И-8a: постквантовый конверт, якоря доверия, ротация, отзыв и защита от отката — работа задачи реестра). До тех пор пакет реестра отклоняется, подписан он или нет, если оператор не задал `allow_unsigned = true` для этого реестра; тогда он устанавливается с предупреждением, что не проверен. Имеющаяся подпись никогда не считается проверенной. Зависимости-каталоги и архивы — не пакеты реестра: их точное содержимое (хеш архива) называет корневой манифест.

Поддерживается только `http://`: для HTTPS нужна реализация TLS, которой у компилятора нет (зависимость для неё пока не добавлена; [compiler/README.md](../../compiler/README.md)). Содержимое пакета связывают его хеш в блокировке и, когда появится проверка, его подпись, а не транспорт.

## 8. Формат архива

Архив пакета — несжатый архив POSIX ustar, какой делает `tar --format=ustar -cf pkg.tar -C pkg .`; файлы могут лежать и внутри одного каталога верхнего уровня. Это стандарт, который пишут существующие инструменты, его фиксированные 512-байтовые заголовки разбираются одной стандартной библиотекой Rust, а несжатый архив не может расшириться: каждый байт каждого файла присутствует в архиве, поэтому распакованный размер не превышает размера архива, который пределы ограничивают до чтения, и атаки через коэффициент распаковки нет. Сжатие спецификацией не требуется; сжатый формат был бы новой версией формата со своим пределом коэффициента.

Принимаются обычные файлы и каталоги с переносимыми относительными именами: буквы ASCII, цифры, `.`, `_`, `-`, `+`. Рабочий процесс распаковки отклоняет, до того как что-либо записано: абсолютные имена, `..`, обратные косые черты и другие символы, имена, которые Windows резервирует или не может сохранить (`CON`, `aux.unio`, точка в конце), символические и жёсткие ссылки, символьные и блочные устройства, FIFO, расширенные заголовки pax и длинные имена GNU, повторяющиеся имена, имена, различающиеся только регистром (они совпадают на файловых системах без учёта регистра, а пакет должен распаковываться везде одинаково), файл там, где нужен каталог, записей больше `entries`, имена глубже `depth`, файлы и пакеты сверх пределов размера, размер, выходящий за конец архива, неверную контрольную сумму заголовка и данные после конца архива. Файлы создаются заново, без битов исполнения и особых битов. Зависимость-каталог копируется по тем же правилам (ссылка в ней отклоняется), без имён, начинающихся с точки, и без `target/` и `unio.lock` в её корне.

## 9. Чего нет

- Проверки подписей и сервиса реестра с подписанной публикацией (И-8, И-8a): следующая задача. До тех пор описанная выше точка проверки отклоняет пакеты реестра, если оператор не принимает их без проверки.
- HTTPS (нет реализации TLS; см. раздел 7).
- Требований к цели и среде выполнения в манифестах (раздел 6 language-contracts требует, чтобы установка их проверяла); манифесты 0.1 их не объявляют.
- `unio publish`, отзыва версий и удаления старых записей кэша.
- В Windows у рабочих процессов пока нет ограничений файлов и сети (SB-4), поэтому рабочий процесс загрузки соединяется сам, а инструментам там нужна более слабая песочница ([runtime.md](runtime.md) 9.7).
