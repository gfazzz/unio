# Эталонный заказчик: tanstaafl

Версия 0.1-draft. Английская версия (основная): `docs/customers.md`.

Язык, задуманный для того, чтобы писать продукты с помощью ИИ, проверяется написанием продукта с помощью ИИ. Таким продуктом служит tanstaafl — B2B-платформа для слаботочных систем безопасности (АПС, СОУЭ, СКУД, видеонаблюдение, СКС, диспетчеризация). Она с помощью ИИ проводит аудит объекта по нормам, генерирует проекты, круглосуточно мониторит объекты с предиктивом и имеет отдельный постквантовый модуль. Её пишет ИИ под ревью человека — именно для такого применения задуман Unio.

Сейчас у tanstaafl сайт на чистом HTML; портала на Rails, с которого всё начиналось, больше нет. ИИ-сервис, агент объекта, событийное ядро и интеграции запланированы на Unio, а не на Python, Rust с драйверами на C, Elixir/OTP и TypeScript, как раньше; пока выпуск Unio не может нести часть, она живёт здесь как сценарий. Каждая часть становится здесь сценарием. Сценарий либо работает в названном выпуске Unio, либо называет, чего этому выпуску не хватает.

## 1. Правила

- Программа сценария лежит в [../../examples](../../examples), использует только стандартную библиотеку из [../../stdlib](../../stdlib) и следует правилам эталонных утилит: использование и коды выхода в документирующем комментарии, блоки `test` написаны до кода. CI проверяет её фронтендом на Rust (`unio check`, `unio fmt --check`) и проверяет использование API; её тесты выполнятся, когда заработает интерпретатор спринта S5 (план, раздел 12).
- Пробел записывается в разделе 4 вместе с целью: существующим требованием, которого он ждёт, выпуском или RFC. Закрытие пробела меняет концепцию, ТЗ или библиотеку обычным порядком (концепция, раздел 1.2; [rfcs/README.md](rfcs/README.md)); этот документ только указывает, куда изменение попало.
- Заказчик сам не добавляет требований. Пробел становится требованием, когда специфицируется выпуск, на который он нацелен.

## 2. Принципы заказчика и что в Unio их держит

| Принцип tanstaafl | Что он требует от языка | Где это есть в Unio |
|---|---|---|
| Человек в контуре: ИИ готовит черновики и находки, значимые действия человек подтверждает подписью | Подтверждение — часть данных; подпись проверяема | Сценарий A не включает неподтверждённые находки в итоги; подписи ждут RC-15 |
| Риски в деньгах: R = P × C, ALE и ROSI; каждая находка аудита ссылается на пункт нормы | Точная арифметика денег; переполнение не бывает молчаливым | Переполнение `Int` — авария, `checked_*` — её безопасные формы (концепция, раздел 3.3); точные деньги ждут `std.decimal` (Б-1), см. RC-2 |
| Данные объекта — это данные, а не инструкции; у агента права стажёра с неизвестной лояльностью | Минимальные полномочия программы; недоверенный текст не становится командой | Полномочия манифеста и песочница (И-6, SB-1); типизированный недоверенный текст — RC-14 |
| Объект живёт без облака 72 часа; облако агрегирует | Запись, переживающая отключение питания; служба, работающая днями | Атомарная и надёжная запись (Б-9) в сценарии B; долгоживущие службы — RC-10 |
| Zero Trust и крипто-гибкость: mTLS, алгоритм — заменяемый параметр | Гибридный постквантовый обмен ключами, версионируемые профили | [cryptography.md](cryptography.md) |

## 3. Сценарии

| ID | Сценарий | Часть tanstaafl | Выпуск Unio | Состояние |
|---|---|---|---|---|
| A | Реестр рисков: находки аудита со ссылками на нормы, ранжированные по годовому ущербу, ROSI каждого исправления, черновики отдельно от подтверждённых находок | Модуль аудита | 0.1 | [../../examples/risk_register.unio](../../examples/risk_register.unio) |
| B | Журнал событий агента объекта: недоставленные события хранятся сколько угодно, доставленные удаляются после окна в 72 часа, при превышении окна — предупреждение | Агент объекта | 0.1 | [../../examples/event_journal.unio](../../examples/event_journal.unio) |
| C | Кадры полевых протоколов: ответ Modbus RTU, прочитанный из байтов и проверенный по CRC-16 | Агент объекта, драйверы протоколов | 0.1 для кадров, 0.2 для портов | Ждёт RC-7, RC-8, RC-9 |
| D | Событийное ядро: служба на объект, принимающая события, ведущая автомат состояний каждой тревоги и перезапускаемая при сбое | Событийное ядро | 0.2 | Ждёт RC-10, RC-11 |
| E | Сайт и клиентский портал: двуязычный сайт, который отдаёт программа на Unio, затем вход и панель объекта поверх PostgreSQL | Сайт, клиентский портал | 0.2 | Ждёт RC-12, RC-13 |
| F | ИИ-сервис: вопрос по нормам, на который LLM отвечает с цитатами; документы объекта никогда не попадают в модель как инструкции | ИИ-сервис | 0.2 | Ждёт RC-14 и HTTPS-клиента 0.2 |
| G | Постквантовый канал между объектом и облаком: mTLS с гибридным обменом ключами, алгоритм выбирается профилем | PQC-модуль | 0.2 | Следует [cryptography.md](cryptography.md) |

Сценарии A и B укладываются в границы 0.1: программы командной строки над файлами и JSON. При их написании найдены RC-1–RC-6.

## 4. Пробелы

| ID | Пробел | Найден в | Зачем он заказчику | Цель |
|---|---|---|---|---|
| RC-1 | Нет преобразования `Float` в `Int`: нет `round`, `floor` или `to_int` с результатом `Option` | A | Частоту 0,05 инцидента в год нельзя превратить в деньги; сценарий A вместо этого считает инциденты на сто лет в `Int` | Библиотека 0.1, `stdlib/core/builtin/float.unio`; без RFC |
| RC-2 | Нет точных десятичных денег | A | Копейкам, НДС и ставкам нужна десятичная арифметика с названным режимом округления; сценарий A использует целые рубли | `std.decimal` из Б-1, этап 5; сценарий A переходит на него |
| RC-3 | Нет `sum` для `List[Int]` и проверяемой суммы | A | Итоги реестра пишутся вручную циклами | Библиотека 0.1, `stdlib/alloc/builtin/list.unio` |
| RC-4 | Нет часов | B | Сценарий B получает NOW аргументом | `std.time` из Б-1, этап 5 |
| RC-5 | Нет надёжного дописывания в файл | B | Каждое подтверждение переписывает весь журнал; на флеш-карте контроллера объекта это время и износ. Нужно `files.open_append(path, durable)` с заданным правилом для оборванной последней строки после отключения питания | Уточнение Б-9 (требование с буквенным суффиксом рядом с ним) |
| RC-6 | Нет блокировки, не пускающей второго писателя в файл | B | Две копии агента переписывали бы журнал каждая, и последнее переименование потеряло бы события другой | Уточнение Б-9 рядом с RC-5 |
| RC-7 | У `Bytes` есть только длина и `to_text`: нет индекса, среза, построения из чисел и чтения 16- и 32-битных чисел в заданном порядке байтов | C | Любой полевой протокол — это кадр байтов | Библиотека 0.1, `stdlib/alloc/builtin/bytes.unio` |
| RC-8 | Нет битовых операций над `Int` | C | CRC-16 Modbus и флаги приёмно-контрольных приборов — это работа с битами | Методы вроде `bit_and`, `bit_xor`, `shift_left` в `stdlib/core/builtin/int.unio` не требуют RFC и сохраняют словарь; операторам RFC понадобится |
| RC-9 | Нет последовательных портов и TCP | C | До приборов добираются по RS-485 и Modbus TCP | 0.2: `std.net`; модуль последовательного порта специфицируется вместе с ним |
| RC-10 | Нет долгоживущей службы: нет ожидания, таймера, упорядоченной остановки по сигналу завершения | B, D | Агент и событийное ядро работают днями и должны останавливаться, не теряя записи | 0.2, задачи |
| RC-11 | Нет надзора: упавшая задача не перезапускается по заданной стратегии | D | Событийное ядро запланировано на OTP именно ради этого | RFC для 0.2 вместе с задачами |
| RC-12 | Нет доступа к базе данных, а FFI закрыт для пользовательского кода (ТЗ, раздел 2.2) | E | Портал хранит данные в PostgreSQL | 0.2: протокол PostgreSQL, написанный на Unio поверх `std.net`, со SCRAM из `std.crypto`; решается при спецификации 0.2 |
| RC-13 | Нет HTTP-сервера, маршрутизации, шаблонов с экранированием, сессий и локализации | E | Весь портал | 0.2 и веб-фреймворк UniOS этапа U-2 ([os.md](os.md)); один фреймворк для обоих |
| RC-14 | У недоверенного текста тот же тип, что у любого другого | F, E | Текст документа объекта не должен попадать в промпт LLM, оболочку, SQL или HTML без явного видимого преобразования | RFC; кандидат в 0.2 |
| RC-15 | Нет подписей | A | Подтверждение находки сегодня — это имя; оно должно стать подписью, которую может проверить третья сторона | 0.2: `std.crypto` с подписями из [cryptography.md](cryptography.md) |

RC-1, RC-3, RC-7 и RC-8 — дополнения библиотеки в рамках 0.1; их можно сделать сейчас, с тестами, в названных слоях. RC-5 и RC-6 меняют Б-9 и проходят через ТЗ. Остальные относятся к спецификации 0.2.

## 5. Что проверено

Обе программы разбираются по [../../spec/grammar.ebnf](../../spec/grammar.ebnf) и вызывают только объявленную стандартную библиотеку (`spec/check_grammar.py`, `spec/check_api.py`). Они проходят фронтенд на Rust: `unio check` не сообщает ошибок (`compiler/unio/tests/sources.rs`), а `unio fmt --check` подтверждает единый стиль — и то и другое в CI. Их тесты выполняются и проходят под `unio test` в интерпретаторе спринта S5, в CI.
