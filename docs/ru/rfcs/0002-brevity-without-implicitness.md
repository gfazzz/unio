# RFC 0002: Краткость без неявности

- Статус: accepted (спецификация, грамматика, корпус, подсветка в редакторах и компилятор: типы параметров лямбд из контекста с E0049, однострочные ветки в синтаксическом анализаторе и форматтере, `expr is pattern` с E0050; [status.md](../status.md), строки Я-8a, Я-33, И-1a)
- Автор: проект Unio при участии Claude
- Дата: 2026-11-06
- Затрагивает: концепцию / ТЗ / грамматику / инструменты
- Английская версия (основная): [0002-brevity-without-implicitness.md](../../rfcs/0002-brevity-without-implicitness.md)

## Кратко

Три изменения убирают главные источники лишнего текста в коде на Unio, не скрывая поведения: типы параметров анонимной функции берутся из ожидаемого типа функции, ветка может содержать одну простую инструкцию в строке заголовка, а `expr is pattern` проверяет образец в условии и связывает его имена в охраняемой ветке. Новое ключевое слово — `is`.

## Мотивация

Разбор примерно 4000 строк на Unio (эталонные программы, стандартная библиотека и инструменты) нашёл три шаблона, которые удлиняют код, не делая его яснее:

```unio
tasks.map(function (task as Task) returns Int: task.id)

match env.get("TODO_FILE"):
    case some(value):
        return Path(value)
    case none:
        return home.join(".todo.json")

match fields.get(key):
    case some(child):
        return child
    case none:
        pass
fail QueryError(message = "no key \"{key}\"")
```

Типы анонимной функции уже заданы `map`; ветки `match` состоят из одной инструкции; последний `match` нужен только для проверки одного варианта.

## Почему существующих конструкций недостаточно

Анонимную функцию нельзя сократить без вывода типов: единственная альтернатива — именованная функция, которая уводит логику от места использования. Ветку в одну строку выразить нельзя: каждому блоку нужна своя строка. Проверка одного варианта требует полного `match`, часто с пустым `case none: pass`. Никакое сочетание существующих конструкций не короче, и каждый из трёх шаблонов встречается почти в каждом файле репозитория.

## Устройство

1. **Типы параметров анонимной функции (Я-8a).** `lambda_param = "named" NAME [ "as" type ] | NAME [ "as" type ]`. Типы и результат можно опустить, когда анонимная функция — аргумент, инициализатор с объявленным типом или возвращаемое значение с известным типом функции; тогда они берутся из этого типа. Везде иначе они обязательны (E0049). Параметры именованных функций, как и раньше, всегда аннотируются.

   ```unio
   tasks.map(function (task): task.id)
   ```

2. **Ветки в одну строку (И-1a).** `branch_block = simple_statement NEWLINE | block` используется в `if`, `else if`, `else`, `case` и `on`. Функции, циклы, `using`, `test`, `try:` и инструкции со строчным обработчиком сохраняют блок. Форматтер пишет ветку из одной простой инструкции в строке заголовка, если строка укладывается в 100 символов, и на следующей строке иначе; поэтому у ветки по-прежнему ровно одна форма записи.

   ```unio
   match env.get("TODO_FILE"):
       case some(value): return Path(value)
       case none: return home.join(".todo.json")
   ```

3. **Проверка образца (Я-33).** `comparison = additive [ comparison_op additive | "is" pattern ]`. `x is some(v)` имеет тип `Bool`. Его имена связаны в ветке, которую охраняет проверка: в теле `if` или `else if`, в теле `while` и в правом операнде `and`, следующем за проверкой. Под `or`, под `not` и после ветки они не связаны; использование там — E0050. Проверка образца не заменяет `match`: значение с несколькими вариантами по-прежнему разбирается полностью.

   ```unio
   if fields.get(key) is some(child): return child
   fail QueryError(message = "no key \"{key}\"")
   ```

## Миграция и диагностика

Существующий код остаётся корректным. Форматтер переносит ветки из одной инструкции в строку заголовка. Для этапа 2 зарезервированы две диагностики:

| Код | Нарушение | Исправление или объяснение |
|---|---|---|
| E0049 | Параметр анонимной функции без типа там, где тип функции не ожидается | Добавить тип или передать функцию туда, где её тип известен |
| E0050 | Имя, связанное `is`, использовано там, где оно не связано | Использовать его внутри охраняемой ветки или применить `match` |

## Альтернативы

- `name: Text` вместо `name as Text`: короче, но меняются все исходники и документы, а выигрыш меньше, чем у этих трёх изменений. Не предлагается.
- Блоки Ruby `{ |x| ... }` и анонимные функции через `=>`: второй синтаксис анонимных функций. Отклонено; существующая форма `function` с выводом типов достаточно близка.
- Неявный `return`, необязательные скобки, `unless`, модификаторы инструкций (`return if x`): несколько форм записи одного смысла, против принципов 1 и 2 концепции. Отклонено.
