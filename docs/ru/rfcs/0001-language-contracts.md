# RFC 0001: Точные контракты языка и библиотеки

- Статус: accepted (спецификация, грамматика и исходники библиотеки; поддержка компилятора ожидается)
- Автор: проект Unio совместно с Codex
- Дата: 2026-11-03
- Затрагивает: концепцию / ТЗ / грамматику / библиотеку / инструменты
- Английская версия (основная): [0001-language-contracts.md](../../rfcs/0001-language-contracts.md)

## Краткое описание

Принимаются полезные находки сравнительного обзора языков. Указание владельца проекта имплементировать находки разрешает это изменение проекта на этапе 0. Нормативные правила находятся в [language-contracts.md](../language-contracts.md), на них ссылается ТЗ. RFC фиксирует пересмотр принятых решений и новое контекстное слово `named`. Принятие RFC не означает готовности интерпретатора, компилятора, менеджера пакетов или ОС.

## Мотивация

Именованные аргументы необязательны даже для непонятных позиционных флагов. `Float` обещает IEEE-сравнения, но `Order.compare` не представляет несравнимость NaN. `range` создаёт полный список, `sorted_by` повторно вычисляет ключ, автоматическое преобразование JSON не разграничено с приватными конструкторами, а рекурсивные хеши символов не имеют определённой модели кеша.

## Почему существующих конструкций недостаточно

Соглашение о стиле не обеспечивает обязательность имени, а структура настроек избыточна для одного флага. `named timeout as Int` помещает требование в сигнатуру, включая значения функций. Результат `Int` у `Order.compare` имеет только три исхода и не сохраняет IEEE-несравнимость. Обёртка `OrderedFloat` сохраняет обычные численные сравнения и предоставляет корректный тип ключа. Список не представляет большой диапазон за постоянную память. Для курсоров и потоков достаточно структур, интерфейсов и `using`; `yield`, `async`, макросы, наследование и динамические приведения не добавляются.

## Проект

В `param` добавляется `"named" NAME "as" type ["=" expression]`. В `function_shape` используется `shape_parameter = "named" NAME "as" type | type`. Модификатор контекстный: `named as Int` остаётся обычным параметром с именем `named`. Обязательно именованные параметры следуют после обычных и не могут быть `var` в 0.1; параметры с умолчаниями завершают каждую группу. Тип функции сохраняет имена, но не умолчания. При вызове обязательны имена и соответствие форме функции. Для lambda действуют те же правила.

```unio
function connect(host as Text, named port as Int = 8080) returns Text:
    return "{host}:{port}"

function apply(callback as Function[(Text, named port as Int) -> Text]) returns Text:
    return callback("localhost", port = 8080)
```

Обычные позиционные или именованные параметры сохраняются. Новые опции следует делать `named`; существующие API мигрируют с диагностикой и исправлением. Инструменты переименования считают имена частью публичного API, включая вызовы значений функций. Изменения Float, диапазонов, импортов зависимостей, хеширования, декодирования и нормализации путей описаны в нормативном документе.

## Миграция и диагностика

RFC резервирует диагностики этапа 2:

| Код | Нарушение | Исправление или объяснение |
|---|---|---|
| E0040 | Пропущено обязательное имя аргумента | Вставить известное имя; не угадывать неоднозначное соответствие |
| E0041 | Неверные группы параметров, умолчания или форма функции | Показать требуемую сигнатуру и проблемный параметр |
| E0042 | Перекрывающиеся исключительные доступы | Сохранить значение аргумента во временную переменную или разделить вызовы |
| E0043 | Потерян значимый результат | Обработать, вернуть или явно связать через `let _ = ...` |
| E0044 | Чужая или перекрывающаяся реализация интерфейса | Назвать владельцев/реализации; предложить локальную обёртку |
| E0045 | IEEE Float использован вместо полного Order | Явный ключ `total_order()` |
| E0046 | Автопреобразование обходит приватные поля | Публичная транспортная структура и проверяющий конструктор |
| E0047 | Range использован как List | Вставить `.to_list()`, если нужна материализация |
| E0048 | Нет идентичности зависимости или есть конфликт | Показать псевдоним, источник, ограничения версий и запись lock |

Это будущие проверки компилятора, а не возможности проверяющего грамматику скрипта. `Path.normalize` сохраняет `..`; для разрешения файловой системой служит `files.resolve`. Повторные ключи JSON вызывают ошибку. У `parse` есть пределы размера и глубины с явным изменением через именованные аргументы. `encode` сохраняет задокументированное преобразование неконечных чисел в `null`; строгие конфигурации и протоколы используют `encode_checked`. У транспортных структур `todo` поля явно публичны. Сравнения Float сохраняют IEEE, обобщённые API полного порядка требуют ключи `OrderedFloat`.

## Альтернативы

Обязательные имена у всех аргументов затрудняют очевидные позиционные данные. Разделитель `*` из Python добавляет пунктуацию без объяснения смысла. Полный порядок вместо IEEE-операторов удивит пользователей численного кода. Полное заимствование, обработчики эффектов, multiple dispatch и макросы этим обзором не обоснованы. Для многострочных lambda и алгебры физических единиц нужны реальные примеры и отдельный RFC.

## Проверка

- Грамматика: корректные объявления, lambda/формы функций и контекстные имена; ошибки отсутствующего типа/имени. Оба инструмента читают общий EBNF.
- Проверки API на Python и Unio извлекают имя параметра после контекстного модификатора; проверяется callback, который сам обязательно именованный.
- Блоки `test`: стабильность сортировки/один элемент, границы коллекций, остановка при ошибке callback, исчерпание курсоров, крайние значения диапазона, дубли JSON, лимиты, Unicode, пути, причины ошибок, воспроизводимое уменьшение контрпримера.
- Приёмка этапов 2–3: E0040–E0048, точное число вычислений ключей, эффекты/ошибки, освобождение ресурсов, приватность декодирования, NaN, рекурсия хешей и конфликты пакетов — по нормативному документу.
- Статические проверки не исполняют поведенческие тесты; исполнение ожидается на этапе 3.
