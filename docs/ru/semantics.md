# Статическая семантика Unio 0.1

Версия 0.1-draft. Изменения в этом черновике: решения, записанные при реализации S3 (1.3, 1.4, 2.5, 2.7, 2.8, 4.1) и S4 (6.5, 6.6, 7.2, 8.2, 8.3), а также консервативный вывод эффектов через интерфейсы, функциональные значения и выражения, выделяющие память (8.4). Английская версия (основная): [../semantics.md](../semantics.md). Основание: разделы 2–6 концепции, требования Я-1–Я-33, [language-contracts.md](language-contracts.md), RFC 0001 и RFC 0002. Этот документ — справочник, который `unio check` реализует в спринтах S3 и S4 плана; при расхождении с ТЗ прав ТЗ, а этот документ исправляется.

`unio check` выполняет все проверки на всём пакете и сообщает каждую найденную ошибку, а не только первую (К-2). Каждое правило ниже называет свою диагностику. Коды E0051–E0085 выделены здесь; столбец «Спринт» говорит, когда компилятор начинает их сообщать. Проверки имён и типов выполняются, только когда разбирается каждый модуль программы: сначала сообщаются синтаксические ошибки.

## 1. Пакеты, модули и имена

1. Пакет — каталог с `unio.toml`; без манифеста корнем пакета считается каталог проверяемого файла. Модуль — файл; его имя — путь от корня пакета, где `/` заменён на `.`, без `.unio`. Имена, начинающиеся с `std.`, — модули стандартной библиотеки (Я-22).
2. Модуль объявляет имена в одном пространстве: функции, константы, структуры, перечисления, ошибки и интерфейсы. Два объявления с одним именем в модуле — E0051. Методы находятся в пространстве своего типа; два метода с одним именем у одного типа — E0051.
3. `import a.b` связывает с модулем имя `b`, а `import a.b as c` — имя `c`; `from a.b import x, y` связывает `x` и `y`. Связанное имя, совпадающее с объявлением или другим импортом модуля, — E0052. Модуль, который не найден, — E0053, как и модуль, чей файл после разрешения ссылок лежит вне пакета или стандартной библиотеки, где он найден: импорт не может вывести за их пределы через символическую ссылку; импортируемое имя, которое модуль не объявляет или не делает публичным, — E0054. Импорт модуля также делает видимыми по коротким именам его публичные типы `error`, потому что обработчики называют ошибки: `on IoError` после `import std.files`. Такое имя, совпадающее с другим видимым именем, — E0052.
4. Прелюдия каждого доступного слоя (Б-11) видна в каждом модуле. Объявление модуля скрывает имя прелюдии с тем же написанием; `some`, `none`, `ok` и `error` объявлять нельзя (Я-6a). Вариант, объявленный или импортированный в модуле, тоже скрывает имя прелюдии, поэтому вариант `Add` перечисления команд можно писать без имени перечисления, хотя в прелюдии есть интерфейс `Add`. Встроенные типы (Я-4) скрыть нельзя: вариант с таким именем пишется полностью (Я-6a).
5. Локальные имена вводят параметры, `let`, `var`, `for`, `using`, `on E as e`, образцы `case`, параметры анонимных функций и `is` (Я-33). Локальное имя видно от места введения до конца блока, который его вводит; связывания `is` подчиняются Я-33. Локальное имя не может повторять локальное имя, видимое в этом месте (E0055): читателю никогда не приходится выяснять, какое из двух одинаковых имён имеется в виду.
6. Имя, которое ни к чему не разрешается, — E0056; исправление предлагает ближайшее видимое имя.
7. Видимость подчиняется Я-23–Я-23d: приватное объявление, поле или метод, использованные из другого модуля, — E0057.
8. Цикл импортов — E0058, сообщение называет модули цикла (Я-24).

## 2. Типы

1. Встроенные типы — те, что перечислены в Я-4. Имя типа с неверным числом аргументов типа — E0059. Имена типов разрешаются как остальные имена (E0056).
2. Тип локального `let` или `var` — тип его инициализатора (Я-8). Инициализатору, который не определяет тип, например `[]`, `{}` или одному `none`, нужна аннотация (E0060).
3. Типы сравниваются по имени и аргументам; неявных преобразований нет (Я-5). Выражение не того типа, который ожидается, — E0061; сообщение называет оба типа, а для `Text + Int` исправление предлагает интерполяцию. Целочисленные литералы имеют тип `Int`, остальные числовые — `Float`.
4. `Never` — тип `fail`, `return`, `break`, `continue` и вызовов функций, возвращающих `Never`; он принимается везде, где ожидается любой тип.
5. Значение типа `T` принимается там, где ожидается интерфейсный тип `I`, когда `T` реализует `I` и `I` можно использовать как тип (Я-6b); иначе E0061, а для интерфейса, который нельзя использовать как тип, E0071 называет мешающий метод. Аргументы типа обобщённого интерфейса сравниваются: значение, реализующее `Iterator[Int]`, не принимается как `Iterator[Text]`; то же верно для ограничений (3.3) и проверки реализаций (3.6).
6. `some(v)` и `none` имеют тип `Option[T]`, `ok(v)` и `error(e)` — тип `Result[T, E]`; недостающий аргумент типа берётся из ожидаемого типа, а без него — E0060.
7. Каждое объявление `error` реализует `Error` с порождаемым `to_text`, который называет тип и его поля, а значит и `Display`: ошибку можно подставить в текст.
8. Выражение, тип которого нельзя определить из-за более ранней ошибки, не порождает новых диагностик: одна ошибка — одно сообщение.

## 3. Объявления, вызовы и обобщения

1. Значение структуры строится с именованными аргументами для каждого поля без значения по умолчанию; пропущенное или неизвестное поле — E0063. Поля, приватные для другого модуля, делают структуру невозможной для построения там (E0057).
2. Вызов сопоставляет позиционные аргументы первым параметрам, а именованные — по имени. Лишние или недостающие аргументы, неизвестное имя или имя, указанное дважды, — E0064. Параметры только по имени и формы функций подчиняются RFC 0001 (E0040, E0041). Значение по умолчанию вычисляется при каждом вызове, который пропускает аргумент.
3. Обобщённые аргументы функции выводятся из её аргументов и ожидаемого результата; когда это невозможно, вызов должен их записать (E0060). Аргумент типа, не удовлетворяющий ограничению `[T with I]`, — E0062.
4. Вызов метода `x.m(...)` ищет `m` в видимых блоках `extend` типа `x`, затем в интерфейсах, которые тип реализует, включая их методы по умолчанию (Я-6c). Функция типа вызывается как `T.f(...)` (Я-23d).
5. Анонимная функция берёт типы параметров и результата из ожидаемого типа функции; где его нет, их нужно записать (E0049, Я-8a).
6. `extend T with I` должен определить каждый метод `I` без реализации по умолчанию с сигнатурой из `I` (где `Self` заменён на `T`); пропущенный метод или другая сигнатура — E0069. Вторая реализация `I` для `T` или реализация в модуле, которому не принадлежат ни `T`, ни `I`, — E0044.
7. Вариант перечисления, краткая форма которого совпадает с видимым именем, пишется с именем перечисления (Я-6a): E0072.

## 4. Операторы и выражения

1. `+`, `-`, `*`, `/`, `%`, `**` требуют, чтобы тип операндов реализовывал `Add`, `Subtract`, `Multiply`, `Divide` (Я-9a); `%` и `**` определены для `Int` и `Float`. Оба операнда одного типа; иначе E0065. У списков нет `+`: их соединяет `append_all`, чтобы копирование списка всегда было видно.
2. `==` и `!=` требуют `Equal`, `<` `<=` `>` `>=` — `Order`; `Float` подчиняется Я-32 (E0045). `==` для ресурса — E0066 с исправлением `is_same(a, b)`.
3. `and`, `or`, `not` принимают `Bool`, кроме `or` с левым операндом `Option[T]`: он даёт `T` с правым операндом `T` или `Option[T]` с правым операндом `Option[T]`. Условия `if`, `while`, `assert` и охранные условия имеют тип `Bool` (E0061).
4. `x in c` вызывает `c.contains(x)`; у `c` должен быть такой метод (E0061).
5. `a?.f` требует `a` типа `Option[T]` и даёт `Option[U]` для поля `f` типа `U`.
6. `items[i]` определено для `List[T]` с индексом `Int` и для `Map[K, V]` с ключом `K`; отсутствие элемента — авария, а `get` — безопасная форма (Я-18).
7. Каждое интерполированное выражение должно реализовывать `Display` (E0067).
8. `x is p` имеет тип `Bool`; его связывания подчиняются Я-33 (E0050).

## 5. Ошибки

1. Вызов функции с `fails with` вне `try` — E0073, в любой позиции (Я-14).
2. Каждая ошибка, которую пробрасывает `try`, должна быть перечислена в `fails with` текущей функции или обработана `on` объемлющего `try:` (Я-15); иначе E0074 называет ошибку, а исправление добавляет её в `fails with`.
3. `fail x` требует `x` типа `error`, который функция перечисляет или который обрабатывает окружающий `try:` (E0074).
4. Блок строчного обработчика не должен завершаться обычным образом (Я-14a): E0075.
5. `try` перед выражением, которое не может завершиться ошибкой, — E0076; исправление убирает его.

## 6. Значения, изменяемость и поток управления

1. Присваивание имени, введённому `let`, параметру, переменной `for` или имени из образца — E0077 (Я-10).
2. Изменение значения через место, которое не начинается с `var`-имени, `var`-параметра или имени `using`, изменение поля, не объявленного `var`, или вызов метода `var self` у такого места — E0078 (Я-11).
3. `var`-параметр принимает `var`-имя вызывающего (E0079); одно имя не может попасть в два `var`-параметра одного вызова (E0042).
4. Функция с результатом, конец которой достижим без `return`, — E0082. `break` и `continue` вне цикла — E0083.
5. `match` должен покрывать каждый вариант своего значения или иметь `case _` (E0068), и E0068 называет недостающие случаи. `match`, образцы списков или кортежей которого складываются в больше случаев, чем перебирает проверка, не считается полным: ему нужен `case _`, и E0068 об этом говорит. После E0068 пропущенный `return` в той же функции повторно не сообщается (2.8). `match` по `Float` — E0061 (Я-9).
6. `Result` или `std.process.Output` нельзя отбрасывать, а локальное имя, которое его держит, должно быть прочитано; `let _ = expression` отбрасывает его явно (E0043, Я-30). Остальные результаты можно не использовать.

## 7. Ресурсы

1. Значение типа, реализующего `Resource`, создаётся только как инициализатор `using` или поля другого ресурса; где-либо ещё — E0080 (Я-20).
2. Ресурс не может покинуть свой блок `using`: сохранение в структуре, коллекции или имени объемлющего блока, возврат или захват в анонимной функции — E0081. Параметр типа ресурса можно использовать и передавать другим функциям, но его сохранение, возврат или захват — тоже E0081. `let`, держащий ресурс, даёт только E0080; дальше имя считается именем `using`, чтобы одна ошибка давала одно сообщение.
3. Ресурс — не значение: его нельзя хранить как значение интерфейса (Я-6b) и сравнивать через `==` (E0066).

## 8. Слои, профили и эффекты

1. Модуль слоя библиотеки может пользоваться только своим слоем и предшествующими (Б-11), а модуль слоя `core` не может выделять память (пункт 4); в пакете `unio check --profile=core` применяет то же правило к каждой функции, которую пакет определяет. Нарушение — E0084, сообщение перечисляет цепочку вызовов от функции до первой функции более высокого слоя или до выражения, выделяющего память, с его строкой (К-21).
2. Эффекты выводятся, а не объявляются (Я-9b). Внешняя функция имеет эффект своего модуля стандартной библиотеки: `std.files` даёт `files.read` или `files.write`, как говорит строка «Permission» функции, `std.env` — `env`, `std.process` — `process`, `std.net` — `network`; любая функция слоя `alloc` даёт `allocates`. Функция имеет объединение эффектов вызываемых ею функций. `unio symbol` показывает их (К-11).
3. Пакет, использующий функцию, эффект которой не разрешён его манифестом, — E0085 с цепочкой вызовов (раздел 6 концепции, И-6). `files.read` и `files.write` проверяются по одноимённым областям манифеста.
4. Вывод консервативен: всё, что может сделать запуск, входит в эффекты и слой, выведенные для функций, через которые он проходит (Я-9b, К-21). Три правила распространяют пункт 2 за пределы прямых вызовов:
   - *Интерфейсы.* Вызов метода интерфейса имеет эффекты и слой каждой реализации этого метода в программе и метода интерфейса по умолчанию; когда тип значения известен, учитывается только метод этого типа. Язык сам вызывает методы интерфейсов, и эти вызовы учитываются так же: `==` и `!=` вызывают `Equal.equals`; `<`, `<=`, `>` и `>=` — `Order.compare`; `+`, `-`, `*` и `/` — методы `Add`, `Subtract`, `Multiply` и `Divide`; интерполяция — `Display.to_text`; `for` — `iterator` и `Iterator.next`; конец `using` — `Resource.release`; `in` — `contains`. Для `Int`, `Float`, `Bool`, `Text`, `Bytes` и `Path` они не вызывают кода на Unio. Тип реализует интерфейс только в своём модуле или в модуле интерфейса (3.6), а `unio check` проверяет программу вместе со всеми модулями, которые она импортирует, поэтому множество реализаций для проверяемой программы замкнуто.
   - *Функциональные значения.* Эффекты функционального значения учитываются там, где значение создаётся: тело лямбды принадлежит функции, которая её содержит, а упоминание функции как значения считается её вызовом; вызов значения ничего не добавляет. Значение создаётся до вызова, в том же запуске, функцией, которая выполняется раньше, поэтому его эффекты входят в эффекты `main` или теста и проверяются по манифесту (E0085) и профилю core там, где значение создано. Функция, которая только вызывает полученное значение, как `List.map`, имеет свои эффекты; эффекты значения имеет вызывающая функция, создавшая его. По той же причине инициализатор константы учитывается в каждой функции, использующей константу, значение параметра по умолчанию — в его функции, а значения полей структуры или ошибки по умолчанию — в каждой функции, создающей её значение, где они вычисляются ([runtime.md](runtime.md) 1.3, 6.3).
   - *Выделение памяти.* Выражение, создающее значение слоя `alloc`, само выделяет память: литерал списка, литерал словаря, генератор списка, текст с интерполяцией, `+` над текстами и лямбда, захватывающая локальное имя или `self`. Оно даёт содержащей его функции, константе или значению поля по умолчанию эффект `allocates` и слой `alloc`, поэтому под `--profile=core` это E0084 с цепочкой, которая заканчивается этим выражением; в модуле слоя `core` это E0084 у самого выражения (пункт 1). Текст без интерполяции и лямбда, которая ничего не захватывает, память не выделяют. В грамматике нет литерала множества: множество создаёт функция слоя `alloc`, что покрывает пункт 2.

   `unio symbol` показывает выведенные так эффекты, а E0085 сообщается у первого вызова, использования константы или значения поля по умолчанию либо неявного вызова каждого модуля, которому нужен эффект, не разрешённый манифестом.
