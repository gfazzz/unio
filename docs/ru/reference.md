# Справочник языка Unio

Версия 0.1-draft. Основная версия на английском: [../reference.md](../reference.md). Требование Д-1: грамматика в EBNF, семантика каждой конструкции и список кодов диагностик.

Этот документ — точка входа в определение языка. Он проходит грамматику конструкция за конструкцией и для каждой говорит, что она значит: чего от неё требует `unio check` до запуска программы и что она делает при выполнении. Нормативные тексты, которые он обобщает, остаются на своих местах; если этот справочник с одним из них расходится, прав нормативный текст, а справочник исправляется:

|---|---|

| Статическая семантика (что проверяет `unio check`) | [semantics.md](semantics.md), разделы 1–8 |
| Динамическая семантика (что делает запуск) | [runtime.md](runtime.md), разделы 1–6 |

Каждое правило грамматики названо ниже в обратных кавычках, например `function_decl`, в разделе той части грамматики, которая его определяет. Полноту документа держат две проверки: шаг CI «Generated references are up to date» запускает `unio run tools/reference.unio -- --check`, и он не проходит, если правило из `spec/grammar.ebnf` здесь не названо или таблица раздела 8 не совпадает со списком кодов каталога компилятора (`compiler/unio/src/catalog.rs`). Как пользоваться языком, рассказывает руководство, [guide.md](guide.md).

## 1. Лексическая структура (раздел грамматики L)

Исходный файл — текст в UTF-8 с расширением `.unio` (Я-1). Концы строк — LF или CRLF; в репозитории хранится LF.

**Строки и блоки.** Логическая строка — строка хотя бы с одним токеном. Блок — подряд идущие строки с отступом ровно на четыре пробела больше, чем у строки, которая его открывает; эта строка заканчивается `:`. Отступ состоит только из пробелов: табуляция — E0001, отступ, не кратный четырём, — E0002, отступ, выросший больше чем на уровень или после строки без `:` в конце, — E0003. Внутри `( )`, `[ ]` и `{ }` концы строк и отступы не учитываются, поэтому длинный вызов или литерал продолжается на нескольких строках; незакрытая скобка — E0009, закрывающая скобка без пары — E0010. Пустые строки и строки только с комментарием ничего не дают.

**Комментарии.** `#` начинает комментарий до конца строки. `##` начинает комментарий документации, который относится к следующему за ним объявлению (Я-3); его показывает `unio symbol`, и из него создаётся справочник стандартной библиотеки. Строки `##` в начале файла, за которыми идёт пустая строка или `unsafe module`, документируют модуль. Комментарии не токены: смысла программы они не меняют.

**Имена.** `letter` — латинская буква ASCII, `digit` — цифра ASCII; `NAME` — буква или `_`, за которыми идут буквы, цифры и `_`, и это не ключевое слово. Другие символы вне текстов и комментариев — E0007. По соглашению функции, переменные, поля и модули пишутся в `snake_case`, типы — в `PascalCase`.

**Ключевые слова.** Неизменный набор ключевых слов 0.1: `and as assert break case continue else enum extend fail fails false for from function if import in interface is let match not on or pass public return returns self struct true try using var while with`; новое слово требует RFC (Я-2). Контекстные ключевые слова `error external module named test unsafe` — обычные имена везде, кроме мест, где их использует правило: начала объявления и `named` перед параметром. `uses` зарезервировано для следующего выпуска (E0032).

**Числа.** `INT` — это `decimal_int` (`1_000`), шестнадцатеричное число `0xFF` из символов `hex_digit` или двоичное `0b1010`; `_` разделяет цифры. У `FLOAT` есть дробная часть, `exponent` или обе (`2.5`, `1e-3`, `6.02e23`). Число, за которым сразу идёт буква, — E0008. `INT` имеет тип `Int`, 64-битное целое со знаком; `FLOAT` — тип `Float`, число IEEE 754 binary64. Целый литерал должен помещаться в `Int`, не больше `9223372036854775807`; литерал, который не помещается, — E0008. Поэтому наименьший `Int` записывается как `-9223372036854775807 - 1` (константа `MINIMUM_INT`).

**Тексты.** `TEXT` пишется между `"` на одной строке (иначе E0005). `text_char` — любой символ, кроме `"`, `\`, `{`, `}` и конца строки. `escape` — это `\n`, `\t`, `\r`, `\0`, `\\`, `\"`, `\{`, `\}` или `\u{...}` с одной–шестью шестнадцатеричными цифрами скалярного значения Unicode; любая другая — E0006. `interpolation` `{expression}` вставляет в текст текстовую форму выражения: оно вычисляется вместе с текстом, слева направо с остальными частями, и его тип реализует `Display` (E0067). Пустая или незакрытая интерполяция или `}` без `\` — E0011. Текст — неизменяемая последовательность скалярных значений Unicode (Б-18).

**Знаки.** `( ) [ ] { } , : . ?. ... = == != < <= > >= + - * / % ** -> |`. Вложенность глубже 64 уровней выражений, образцов, типов, блоков или интерполяций — E0013.

## 2. Файлы и объявления (раздел грамматики F)

**`file`.** Файл — это модуль (Я-22): необязательный `module_header`, затем элементы `top_item`, каждый из которых — `import`, `declaration`, `extend_decl` или `test_block`. Имя модуля — путь от корня пакета, где `/` заменён на `.`, без `.unio`; корень пакета — каталог ближайшего `unio.toml`. Элементы верхнего уровня идут в любом порядке, и имя можно использовать раньше строки, которая его объявляет.

**`module_header`.** `unsafe module` отмечает модуль, вынесенный на проверку (И-6, И-9, RFC 0004). В стандартной библиотеке только в таком модуле может стоять `external_decl` (Б-7). В пакете отметка ничего не даёт: ни внешних функций (E0086), ни разрешений, ни других правил.

**`import` и `module_path`.** `import a.b` связывает `b` с модулем `a.b`, `import a.b as c` связывает `c`, а `from a.b import x, y` — публичные имена `x` и `y` модуля. `module_path`, который начинается с `std.`, называет стандартную библиотеку, `deps.<псевдоним>.<модуль>` — зависимость, зафиксированную в `unio.lock` (И-14), любой другой путь — модуль того же пакета (`a.b` — это файл `a/b.unio`). Импорт модуля делает видимыми по коротким именам и его публичные типы `error`. Ошибки: модуль не найден или ссылка ведёт за пределы пакета (E0053), имя не объявлено в модуле публично (E0054), имена совпадают (E0052), цикл импортов (E0058), путь `deps.`, которого нет в манифесте, файле блокировки или кэше (E0048). Семантика 1.3, 1.8, 1.9.

**`declaration`.** Функция, внешняя функция, структура, перечисление, ошибка, интерфейс или константа, перед которыми может стоять `public`. Всё закрыто в своём модуле, если не помечено `public` (Я-23); закрытое объявление, использованное из другого модуля, — E0057. Модуль объявляет каждое имя один раз (E0051); объявление скрывает имя прелюдии с тем же написанием, но не встроенный тип (семантика 1.4).

**`function_decl` и `function_sig`.** `function name[T](item as T, count as Int) returns R fails with E1, E2:`, затем `block`. Без `returns` функция ничего не возвращает; с ним каждый путь заканчивается `return` или `fail` (E0082). `fails with` перечисляет ошибки, которыми функция может завершиться (Я-13): тело выпускает наружу только их (E0074), а каждый вызывающий пишет `try` или обрабатывает их (E0073). Вызов один раз вычисляет получателя и аргументы слева направо в порядке записи, затем значения по умолчанию пропущенных параметров в порядке объявления (Я-27, runtime 1.1, 1.3). Функции — значения: функция, названная без вызова, — значение типа `Function[(...) -> T]`.

**`external_decl`.** `external function f(...) returns T` объявляет функцию, которую реализует среда выполнения, без тела. Объявлять её может только `unsafe module` стандартной библиотеки (E0086); её комментарий документации — её спецификация (runtime 7).

**`generic_params` и `generic_param`.** `[T, K with Hash and Equal]` объявляет параметры типа функции, структуры, перечисления, интерфейса или `extend`. `with I and J` ограничивает параметр типами, которые реализуют эти интерфейсы; аргумент типа, который их не реализует, — E0062 (E0045 для типа из `Float` там, где нужны `Order` или `Hash`). Аргументы типа выводятся из аргументов и ожидаемого типа или пишутся при вызове (`generic_call`); если их нельзя вывести — E0060. Обобщённая функция разрешается при компиляции, а не диспетчеризуется (Я-7).

**`params` и `param`.** Параметр — `name as Type`, возможно со значением по умолчанию `= expression`. `var name as Type` позволяет функции менять переменную вызывающего: тот передаёт имя `var` (E0079), и одна переменная не может попасть в два параметра `var` одного вызова (E0042, Я-29). `named name as Type` — параметр только по имени: каждый вызов пишет его метку (E0040). Обычные параметры идут раньше параметров только по имени, а значения по умолчанию — в конце каждой группы (E0041, RFC 0001). `self` или `var self` первым параметром делает функцию в блоке `extend` методом; методы `var self` меняют получателя и требуют изменяемого места (E0078). Значение по умолчанию вычисляется заново при каждом вызове, который пропускает аргумент, и видит параметры перед ним (семантика 3.2).

**`struct_decl`, `field_block` и `field`.** Структура — запись с именованными полями; она создаётся как `Task(id = 1, title = "x")` с именованным аргументом для каждого поля без значения по умолчанию (E0063). Поле — `name as Type`, возможно с `var` (его можно менять через изменяемое место) и `public` (видно вне модуля; Я-23a), и с необязательным значением по умолчанию, которое вычисляется при каждом создании, где поле пропущено. Структуру с закрытым полем можно создать и изменить через это поле только в её модуле. Структуры — значения: равенство по содержимому, если у каждого поля есть `Equal` (Я-9), а связывание, передача и хранение копируют значение, насколько это можно наблюдать (Я-11a; по runtime 2.4 оно разделяется, пока его не изменят).

**`error_decl`.** `error Name:` с полями объявляет тип ошибки; он реализует `Error` и `Display` со сгенерированным `to_text` и устойчивым `diagnostic_code` (семантика 2.7, Б-20). Его поля видны везде, где виден тип (Я-23b). Ошибка без полей пишется `error Name` в одну строку. Значение ошибки выбрасывает `fail` и принимает `on`.

**`enum_decl`, `variant` и `variant_field`.** Перечисление — закрытый тип-сумма: значение — ровно один вариант `variant`, у которого могут быть именованные поля (`Add(title as Text)`). Вариант создаётся как `Command.Add(title = "x")` или по краткому имени `Add(...)`, если это имя ни с чем видимым не совпадает (Я-6a, иначе E0072); вариант с полями можно создать и позиционными аргументами в порядке полей. Варианты проверяют `match`, `is` и образцы. Равенство — по содержимому.

**`interface_decl` и `interface_member`.** Интерфейс — набор сигнатур методов (`function_sig`). У члена с блоком `block` есть реализация по умолчанию, которая обращается к значению только через методы интерфейса (Я-6c). Внутри интерфейса `Self` — реализующий тип. Интерфейс — это ограничение (`[T with Shape]`, разрешается при компиляции) и тип: значение типа `Shape` хранит значение любого типа, который его реализует, а вызов на нём при выполнении попадает в метод этого типа (Я-6b). Интерфейс, методы которого используют `Self` не только как получателя или имеют параметры типа, типом быть не может (E0071). У интерфейсного значения нет `==`. Ресурс не может быть интерфейсным значением.

**`extend_decl` и `member`.** `extend T:` добавляет типу того же модуля методы (с `self`) и функции типа (без `self`, вызываются как `T.f(...)`, Я-23d); такой член закрыт, если не `public` (Я-23c). `extend T with I:` реализует интерфейс `I` для `T`: определяет каждый метод `I` без реализации по умолчанию с сигнатурой из `I` (E0069) и может заменить реализации по умолчанию. Его методы видны везде, где видны и `T`, и `I`, и `public` там не пишется. Тип реализует интерфейс один раз, в пакете типа или интерфейса (E0044, Я-31): реализация может быть в любом модуле этого пакета. Из таких реализаций берутся операторы: `extend Money with Add` даёт `+` (Я-9a). `extend[T] List[T]:` расширяет обобщённый тип со своими параметрами типа.

**`constant_decl`.** `let NAME as Type = expression` верхнего уровня объявляет константу модуля. Тип можно опустить только у закрытой константы, инициализатор которой его определяет (Я-8). Константы вычисляются один раз в порядке зависимостей до `main` или до первого теста, которому они нужны; сбой в инициализаторе завершает программу (runtime 6.3). Глобального изменяемого состояния нет: `var` верхнего уровня не существует.

**`test_block`.** `test "описание":` с блоком — тест. `unio test` выполняет каждый тест заданных модулей отдельно и в свежем состоянии; `unio run` и `unio build` тесты пропускают (Я-25, И-4). Тест проходит, если его блок завершается обычным образом, и не проходит при сбое (невыполненный `assert`, `assert_fail`) или если не компилируется — тогда об этом сообщается только для него (И-5a). `expect_fault(action)` успешен, только если действие завершается сбоем (И-5).

## 3. Инструкции (раздел грамматики S)

**`block` и `statement`.** Блок — одна или несколько инструкций, выполняемых по порядку. Пустой блок — синтаксическая ошибка; `pass` — инструкция, которая ничего не делает (Я-2a). `statement` — это `simple_statement` на своей строке или составная инструкция с блоком.

**`simple_statement`.** `let_statement`, `assignment`, `return_statement`, `fail_statement`, `assert_statement`, `break`, `continue`, `pass` или выражение `expression`, вычисляемое ради действия. Инструкция-выражение может отбросить значение вызова, кроме `Result` и `std.process.Output`: их нужно использовать или отбросить явно через `let _ = ...` (E0043, Я-30).

**`let_statement`.** `let name = expression` связывает неизменяемое имя; `var name = expression` — переменную, которую можно присваивать и менять (Я-10). `as Type` задаёт тип имени; без него тип равен типу инициализатора, а инициализатору без собственного типа (`[]`, `{}`, `none`) аннотация нужна (E0060). Локальное имя не может повторять видимое локальное имя (E0055); оно видно со следующей инструкции до конца своего блока. `let _ = expression` вычисляет выражение и явно отбрасывает значение.

**`assignment` и `place`.** `place = expression` сохраняет значение. Место — имя, поле `a.b` или элемент `a[i]` (иначе E0030), и начинается оно с имени `var`, параметра `var` или имени `using` (E0077, E0078); поле меняется, только если объявлено `var`. Сначала определяется место назначения вместе с индексами, затем вычисляется правая часть, и значение сохраняется, только если она вычислилась успешно (Я-27). Изменение элемента коллекции меняет коллекцию: `tasks[index].done = true` (Я-11). Присваивание несуществующему элементу списка — сбой; присваивание ключу словаря вставляет или заменяет значение, а часть значения внутри словаря меняется через его ключ, `books[id].borrower = member`, и это сбой, если ключа нет.

**`return_statement`.** `return expression` завершает функцию с результатом; `return` без выражения завершает функцию без результата. Сначала освобождаются открытые блоки `using`.

**`fail_statement`.** `fail expression` завершает функцию ошибкой: выражение имеет тип `error`, который функция перечисляет в `fails with` или который обрабатывает охватывающий `try:` (E0074). Его тип — `Never`.

**`assert_statement`.** `assert condition` ничего не делает, если условие `Bool` истинно, и вызывает сбой с текстом условия, если ложно (runtime 4.4). Это средство для тестов и инвариантов, которые правильная программа не нарушает; ожидаемая неудача — ошибка, а не сбой.

**`break`, `continue`, `pass`.** `break` выходит из ближайшего `for` или `while`, `continue` начинает его следующую итерацию; вне цикла оба — E0083. Выход из цикла освобождает блоки `using`, открытые внутри него.

**`if_statement`.** Условия имеют тип `Bool` (E0061) и вычисляются по порядку, пока одно не окажется истинным; выполняется его ветвь, а если истинных нет — ветвь `else`. Имя, связанное через `is` в условии, видно в этой ветви (Я-33).

**`for_statement`.** `for item in collection:` один раз вычисляет коллекцию и выполняет блок для каждого её элемента по порядку: `List` от первого к последнему, `Range` от начала к концу, `Set` в порядке вставки; цикл берёт один курсор от `iterator()` и продвигает его раз за итерацию (Б-15), поэтому изменение исходной переменной внутри цикла итерацию не меняет. С несколькими именами `for index, item in items.enumerate():` разбирает каждый элемент как кортеж. Словарь обходится парами `(ключ, значение)`, `for name, age in ages:`, в порядке первой вставки ключей; `keys()` и `values()` дают одну сторону. Имена цикла неизменяемы (E0077).

**`while_statement`.** `while condition:` вычисляет условие `Bool` перед каждой итерацией и выполняет блок, пока оно истинно. Имя, связанное через `is` в условии, видно в блоке.

**`match_statement` и `case`.** `match subject:` один раз вычисляет проверяемое значение и пробует ветви по порядку; выполняется ветвь первого `case`, образец `pattern` которого подходит и охранное условие `if` которого, вычисленное с именами образца, истинно, а другие ветви не выполняются. Ветви покрывают каждое значение, или последняя — `case _`; ветви с охранными условиями в этом не участвуют (E0068 называет недостающие варианты). Проверяемое значение типа `Float` — E0061: образцов для `Float` нет (Я-9). Имена из образца неизменяемы и видны в охранном условии и в ветви.

**`try_statement` и `handler`.** `try:` выполняет свой блок, в котором вызов функции с `fails with` не требует приставки `try`. Если ошибка покидает блок, выполняется первый обработчик `on Type as name:`, тип которого — тип ошибки или `Error` для любой ошибки, с ошибкой в имени, и выполнение продолжается после инструкции. Ошибка, которую не принял ни один обработчик, уходит к вызывающему и должна быть перечислена в `fails with` (E0074). Сбой `on` не принимает никогда (Я-17).

**`handled_statement`, `handled_head` и `inline_handler`.** `let x = try f() on E as e:` с блоком обрабатывает одну ошибку выражения `try`, которым заканчивается инструкция; заголовок — `let`, присваивание, `return` или выражение. Если `f` успешна, инструкция завершается с её значением; если она завершилась ошибкой `E`, выполняется блок, и он не должен завершаться обычным образом: он заканчивается `return`, `fail`, `break`, `continue` или вызовом функции, которая не возвращает (E0075, Я-14a). Один обработчик на инструкцию, в её конце (E0024).

**`branch_block`.** Ветвь `if`, `else if`, `else`, `case` или `on` с одной простой инструкцией можно записать на строке заголовка: `case none: return 0` (RFC 0002). `unio fmt` оставляет её там, если строка укладывается в 100 символов (И-1a). У функций, циклов, `using`, `test`, `try:` и инструкций с обработчиком всегда есть блок.

**`using_statement`.** `using name = expression:` создаёт ресурс (значение типа, реализующего `Resource`), связывает его и выполняет блок. Когда блок завершается — обычным образом, через `return`, `break`, `continue`, ошибкой или сбоем, — `release` ресурса выполняется ровно один раз; вложенные блоки `using` освобождаются в обратном порядке (Я-21, runtime 5). Ресурс создаётся только здесь или как поле другого ресурса (E0080), не может покинуть свой блок через сохранение, возврат или захват (E0081) и сравнивается через `is_same`, а не `==` (E0066). Имя — место: можно вызывать его методы `var self`, но присвоить его заново нельзя.

## 4. Выражения (раздел грамматики E)

Приоритет от низшего к высшему, как его задаёт грамматика:

| Уровень | Операторы | Ассоциативность |
|---|---|---|
| 1 | `a if c else b` | правая |
| 2 | `or` | левая |
| 3 | `and` | левая |
| 4 | `not` | префиксный |
| 5 | `==` `!=` `<` `<=` `>` `>=` `in` `not in` `is` | нет (E0020) |
| 6 | `+` `-` | левая |
| 7 | `*` `/` `%` | левая |
| 8 | `-` (отрицание), `try` | префиксные |
| 9 | `**` | правая |
| 10 | вызов, обобщённый вызов, индекс, `.`, `?.` | постфиксные |

Вычисление строгое и идёт слева направо (runtime 1.1, Я-27). Неявных преобразований нет (Я-5): операнды оператора одного типа (E0065), а выражение не того типа, который ожидается, — E0061.

**`expression`.** Это `lambda` или `conditional`.

**`lambda` и `lambda_param`.** `function (x as Int) returns Int: x * 2` — анонимная функция, тело которой — одно выражение. Типы параметров и результата можно опустить там, где ожидается тип функции, например в аргументе: `tasks.map(function (task): task.id)` (Я-8a); в других местах они обязательны (E0049). Лямбда может объявлять `fails with`. Она захватывает значения используемых имён в момент создания и не может их присваивать (Я-11a). Её эффекты учитываются там, где её вызывают (семантика 8.4).

**`conditional`.** `a if c else b` вычисляет `Bool` `c`, затем только выбранную ветвь; у обеих ветвей один тип.

**`or_expr`, `and_expr` и `not_expr`.** `and`, `or` и `not` принимают `Bool`; `and` и `or` вычисляют правый операнд, только если левый не решает результат (runtime 1.2). `option or fallback` с `Option[T]` слева даёт значение из `some` или вычисляет запасное значение для `none`: запасное `T` даёт `T`, запасное `Option[T]` даёт `Option[T]` (семантика 4.3).

**`comparison` и `comparison_op`.** `==` и `!=` требуют `Equal`; `<`, `<=`, `>`, `>=` требуют `Order`, кроме `Float`, который сравнивается по IEEE 754, где любое сравнение с NaN ложно (Я-32). Сравнения не образуют цепочек (E0020). `a in c` вызывает `c.contains(a)`, `not in` — его отрицание. `x is pattern` — `Bool`, проверяющий образец; его имена связаны в ветви, которую проверка охраняет, в правом операнде следующего `and` и больше нигде (E0050, Я-33). `==` для ресурса — E0066.

**`additive` и `multiplicative`.** `+`, `-`, `*`, `/`, `%` для `Int` и `Float` и `+` для двух текстов, который их соединяет; пользовательский тип получает их, реализуя `Add`, `Subtract`, `Multiply`, `Divide` (Я-9a). Для `Int` переполнение, деление на ноль и `%` на ноль — сбои; `/` округляет к нулю, а `%` имеет знак левого операнда (runtime 2.1). `Float` следует IEEE 754 и сбоев не вызывает. У списков нет `+`: их соединяет `append_all`.

**`unary`.** `-x` меняет знак числа. `try x` вычисляет выражение, которое может завершиться ошибкой, — вызов функции с `fails with` или значение `Result` (Я-16) — и передаёт ошибку вызывающему без изменений; он обязателен перед таким вызовом вне блока `try:` (E0073), а перед выражением, которое не может завершиться ошибкой, — E0076.

**`power`.** `a ** b` возводит `Int` или `Float` в степень; связывает сильнее отрицания, так что `-2 ** 2` равно `-4`, и справа налево, так что `2 ** 3 ** 2` равно `2 ** 9`. Для `Int` переполнение и отрицательный показатель — сбои.

**`postfix`.** `primary`, за которым идут вызовы, обобщённые вызовы, индексы, обращения к полям и безопасные обращения в любом числе, применяемые слева направо.

**`call` и `argument`.** `f(a, b, name = c)` вызывает функцию, функциональное значение, метод (`x.m(...)`), функцию типа (`T.f(...)`), конструктор структуры или варианта. Позиционные аргументы идут первыми (E0023) и связываются с начальными параметрами; именованные связываются по имени в любом порядке, не меняя порядка вычисления. Неверное число, неизвестное имя или имя, данное дважды, — E0064. Метод ищется в блоках `extend` типа получателя, затем в интерфейсах, которые тип реализует, включая их реализации по умолчанию (семантика 3.4).

**`generic_call`.** `json.decode[List[Task]]` перед аргументами вызова записывает аргументы типа, которые вызов не может вывести. `[` после выражения начинает аргументы типа, если первый токен — имя с заглавной буквы, а за парной `]` сразу идёт `(`; иначе это индекс.

**`index`.** `items[i]` читает элемент `List` по позиции `Int` или значение `Map` по ключу; отсутствующий элемент или ключ — сбой, а `get` — безопасная форма, возвращающая `Option` (Я-18). На месте `var` ему можно присваивать.

**`field_access`.** `a.b` читает поле структуры, ошибки или значения варианта либо называет метод для вызова. Закрытое поле другого модуля — E0057.

**`safe_access`.** `a?.b` для `Option[T]` даёт `some(a.b)`, если `a` — `some`, и `none` без вычисления остатка цепочки, если `none` (Я-12, Я-27).

**`primary`.** Число, текст, `true`, `false`, `self` (получатель внутри метода), имя, выражение в скобках, кортеж, список или словарь.

**`tuple`.** `(a, b)` — значение типа `Tuple[A, B]`; кортеж из одного элемента — `(a,)`. Кортеж разбирают образец кортежа или `for a, b in ...`.

**`list` и `comprehension`.** `[a, b, c]` — `List[T]` с элементами одного типа; `[]` требует ожидаемого типа. `[e for x in c if g]` один раз вычисляет `c`, затем для каждого элемента условие `g` и, где оно выполнено, `e` и даёт список результатов по порядку (runtime 1.5); несколько имён разбирают кортежи, как в `for`.

**`map` и `map_entry`.** `{key: value, ...}` — `Map[K, V]`, ключи которого реализуют `Hash` и `Equal` (`Float` ключом быть не может, E0045). Пары вычисляются по порядку, повторённый ключ сохраняет последнее значение; обход идёт в порядке первой вставки ключей. `{}` требует ожидаемого типа. Литерала множества нет: множества создают `Set[T]()` и `List.to_set()`.

## 5. Образцы (раздел грамматики P)

Образцы стоят после `case` и `is`. Образец либо подходит к значению, связывая имена с его частями, либо нет; сопоставление ничего не вычисляет, кроме проверяемого значения.

**`pattern`.** Одна или несколько альтернатив через `|`, которые пробуются слева направо; первая подошедшая связывает свои имена.

**`bind_pattern`.** `p as name` подходит туда же, куда `p`, и дополнительно связывает всё значение с `name`.

**`primary_pattern`.** `_` подходит ко всему и ничего не связывает; остальные формы описаны ниже.

**`literal_pattern`.** Целое число, возможно отрицательное, текст, `true` или `false` подходит к равному значению. Образцов `Float` нет (Я-9).

**`pattern_name`.** Имя, обозначающее вариант без полей (`Show`, `Command.Show`, `none`), подходит к этому варианту; любое другое одиночное имя связывает значение с новым неизменяемым локальным именем.

**`constructor_pattern` и `pattern_arg`.** `Add(title)`, `some(value)`, `error(e)` или `Shape.Circle(radius = r)` подходит к варианту и затем сопоставляет его поля с аргументами: позиционные — в порядке полей, именованные — по имени поля.

**`list_pattern` и `list_element`.** `[a, b]` подходит к списку ровно такой длины поэлементно. `name...` подходит к остатку списка, возможно пустому, как к новому списку; он не больше одного и стоит последним (E0034): `case ["add", rest...] if not rest.is_empty():`.

**`tuple_pattern`.** `(a, b)` подходит к кортежу из стольких же элементов поэлементно.

## 6. Типы (раздел грамматики T)

**`type`, `type_name` и `type_argument`.** Тип — имя, возможно уточнённое модулем (`files.IoError`), с аргументами типа в скобках: `List[Task]`, `Map[Text, Int]`, `Result[Int, ParseError]`. Неверное число аргументов типа — E0059; неизвестный тип — E0056. Встроенные типы — `Int`, `Float`, `Bool`, `Text`, `Bytes`, `List[T]`, `Map[K, V]`, `Set[T]`, `Option[T]`, `Result[T, E]`, `Tuple[...]`, `Path`, `Function[...]` и `Never` (Я-4); внутри интерфейса `Self` обозначает реализующий тип. Типы сравниваются по имени и аргументам (семантика 2.3): два объявления с одним именем в двух модулях или двух пакетах — два разных типа.

**`function_shape` и `shape_parameter`.** Аргумент `Function` — форма функции: `Function[(Int, Text) -> Bool]`, `Function[(T) -> U fails with E]`, `Function[(named limit as Int) -> Int]`. Функциональное значение подходит к форме, если совпадают типы параметров, результат, ошибки и именованные метки; значений по умолчанию у формы нет (Я-28). Без `->` функция ничего не возвращает.

**`type_list`.** Типы после `fails with` в сигнатуре или форме, через запятую. Порядок не важен.

**`Option`, `Result` и `Never`.** `Option[T]` — это `some(value)` или `none` (Я-12); `Result[T, E]` — обычное перечисление с `ok(value)` и `error(value)`, которое существует только там, где оно объявлено или явно создано (Я-16). `Never` — тип `fail`, `return`, `break`, `continue` и вызовов, которые не возвращают; он подходит везде, где ожидается тип.

## 7. Программы, пакеты и граница языка

- **Программы.** Программа начинается с `public function main()` модуля, переданного `unio run` или `unio build`; у `main` нет параметров (аргументы берутся из `std.args.list()`) и нет `fails with`, а любая другая сигнатура — E0090. Её код завершения — 0 или `Int`, который возвращает `main`, от 0 до 100. Сбой завершает её с кодом 101 после освобождения открытых ресурсов, исчерпание памяти или времени — с кодом 102, невыполнимая политика — с кодом 103 (К-15, runtime 6).
- **Ошибки и сбои.** Ошибка — значение в сигнатуре, которое обрабатывают `try` и `on`; сбой — ошибка программиста или исчерпанная проверка, которая управляемо завершает программу и не обрабатывается (концепция, раздел 3).
- **Пакеты и разрешения.** Пакет — каталог с `unio.toml` (И-6, [packages.md](packages.md)). Эффекты каждой функции (`files.read`, `files.write`, `env`, `process`, `network`, `allocates`) выводятся из её вызовов (Я-9b) и должны быть разрешены манифестом (E0085); `allocates`, `clock` и `random` не требуют разрешения, а пакет без манифеста или без таблицы `[permissions]` не разрешает ни одного из остальных. Сам манифест проверяется целиком (E0088), а его `unsafe_modules` должен называть ровно модули с пометкой `unsafe module` (E0089). Каждый запуск идёт в песочнице, которую описывают эти разрешения (SB-1, runtime 9).
- **Слои и профили.** У стандартной библиотеки слои `core`, `alloc` и `std`; модуль слоя и пакет, проверяемый с `--profile=core`, не используют ничего выше разрешённого (E0084, E0087; семантика 8).
