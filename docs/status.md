## Legend

Status of a requirement:

- **met**: the behavior the requirement states exists, and named automated checks of it passed in CI on this code: for a rule that does not depend on the platform, in a green job of E1 (E2 only for code that `9ba5d43` did not change); for the sandbox, the processes, and a rule that names platforms, on each platform it covers. A requirement on documentation is met when the document says what the requirement asks.
- **partial**: something is missing; the row says exactly what.
- **not met**: none of the behavior exists.

Closing, for a row that is not met: **fix** (code, tests, or documentation work), **fix or RFC deferral** (either closes it; the project lead decides, and no deferral is assumed), **evidence pending** (a CI run or a human task the row names). A row may need more than one.

Checks: `tests/X.rs` is `compiler/unio/tests/X.rs`; `runtime tests/X.rs` is `compiler/unio-runtime/tests/X.rs`; "spec corpus" is `spec/tests/valid` and `spec/tests/invalid`; "semantic corpus" is `spec/tests/semantic`, run by `tests/semantic.rs`; "test blocks" are the `test` blocks of `stdlib/`, `examples/`, `docs/examples/`, `docs/ru/examples/`, and `tools/`, run by `unio test` in the step "Unio test blocks" of the jobs `spec` and `native-linux-arm`.

Platforms: **Lx64** Linux x86-64 (`ubuntu-24.04`), **La64** Linux arm64 (`ubuntu-24.04-arm`), **mac** macOS arm64 (`macos-26`), **Win** Windows x86-64 (`windows-2025-vs2026`). The jobs `compiler` and `spec` run on Lx64, mac, and Win; `native-linux-arm` runs on La64 the code generation tests, the native suite, the sandbox suites, `cargo test` of both crates, and every test block; `benchmarks`, `python-parity`, and `editors` run on Lx64; `release`, `install`, and `reproducible` run on all four and have not run on this code. CI sets `UNIO_REQUIRE_PREREQUISITES=1`, so a test whose prerequisite is missing fails instead of passing unrun, and no test or job allows the weaker sandbox (`release_checks_refuse_the_weaker_sandbox` in `tests/sandbox.rs`). "Win E1" in a row means that the named checks passed in the job of E1 on Win.

Native targets: a target counts as done only after its test executables have run on it and the runtime guarantees have been checked there (faults, traces and exit codes, the stack limit, the reserve for `release` of C-17, the operating-system sandbox of the platform, the refusal of an incompatible image with code 104), not after successful linking or a verified object file ([plan.md](plan.md) section 12, step 6). ## Known gaps

The gaps found by the audit of the sprints S1 to S6 and since, numbered as in [plan.md](plan.md) section 12, in their state at `9ba5d43`. A gap that remains is an open item above or a limit named in its rows.

1. **Runtime type identity.** Fixed in `fcb06d3`: values of declared types carry the identity of their declaration in the interpreter and native code (`tests/interpreter.rs`, `tests/native.rs`, fixture `tests/programs/same_names/`).
2. **Indirect effects and allocation by literals.** Fixed in `fcb06d3` and by RFC 0005 (accepted): interface calls take the union of the implementations, calls through function values the effects of every value the callee can be, allocating expressions give `allocates` (E0084), and an estimated call needing a higher layer under `--profile=core` is E0087 (`tests/symbol.rs`, `tests/effects.rs`, `tests/catalog.rs`). What RFC 0005 accepts remains: the analysis is not context-sensitive, the interface union is program-wide, estimates are conservative and complete only for the closed program.
3. **Children of `process.run`.** Children get only granted variables and `PATH`, run in their own process group (on Windows a Job Object they join while suspended), and the whole tree ends at the deadline; output is capped at 16 MiB per stream and counted in the heap with a queue of 384 KiB; on Linux a seccomp filter denies `setsid` and `setpgid` to every descendant; on macOS a descendant that left the group is found through its parents and the marker of the Seatbelt profile. `limits.processes` counts every process of the trees of the children: Linux fails each creation past the limit with `EAGAIN` (a seccomp listener), Windows stops a tree that started more, and on macOS (RFC 0011) a child under a limit can start no process, a program run as root does not start (103), and a set-ID file is not executed. Remaining: on Linux a program that needs `setsid` fails in a child; on macOS an orphan that left the group is found only by the marker, so not without a sandbox, and the marker relies on `sandbox_check`, which has no public header; Ctrl-C does not reach the child group; on Windows a tree that started more than the limit is stopped rather than refused. Tests: `runtime tests/process.rs`, `runtime tests/process_windows.rs`, `tests/sandbox.rs`, `tests/workers.rs`; two of them failed in E1 (O-2).
4. **Imports through symbolic links.** Fixed in `fcb06d3`: a module whose resolved path leaves the package or the library is E0053 (`tests/semantic.rs`).
5. **Heap accounting.** Fixed by RFC 0010: the global allocator counts every block the program requests and refuses one over `limits.heap_bytes`; a refusal, of the limit or of the system, ends with 102 and the preallocated diagnostic, and a fallible reservation of the runtime receives it and unwinds; the 1 MiB reserve for `release` lies within the limit (`heap.rs`, `reserve.rs`; tests in rows C-17, C-18). Remaining, as C-18 allows: what the allocator adds to blocks is not counted (measured up to +54%) and is bounded by `RLIMIT_AS` on Linux and a Job Object on Windows, with no bound on macOS; the out-of-memory killer can end a process without 102. The stack is not always bounded: `==` and the hashing of a key recurse with the depth of a value (gap 9).
6. **Operating-system rules wider than the manifest.** Writes are closed: a writer process (on Windows a second AppContainer) performs every write and checks the write scopes. Starting programs is closed to the listed programs, the interpreters of listed scripts, and on Linux the dynamic loader. Wider than the list: on Linux the loader runs any ELF program a child can read, the libraries it loads run as code, and a listed interpreter runs any readable script; the library directories are readable as a whole; `stat` is not restricted; a read root that does not exist at start grants nothing; a write scope whose directory does not exist at start cannot be written. The check-to-use races are closed on Linux, macOS, and Windows (release condition 5; `runtime tests/files.rs`, `a_link_swapped_in_after_the_check_reveals_nothing_outside_the_scope`). Rows SB-2, SB-4, SB-8, R-7a.
7. **The sandbox of Windows.** Implemented in `c51c141`: a program runs on a thread that impersonates a token of a fresh AppContainer with grants on exactly its read scopes and listed programs; its children and the workers of the tools are processes of AppContainers without capabilities, so no network; writes go through a second container with the write grants; a Job Object holds each tree. Neither the tests nor CI allow the weaker sandbox, and the Win job of E1 passed with it. Remaining: reading is wider by what every application package may read (the system directories, `Program Files`), and a child can run programs there; a child can write the folder of its own profile, deleted with it; only foreign native code could return the thread of a program to the token of the process; a run ended from outside leaves inert entries of a dead SID in DACLs; granting a large tree takes time in proportion to its size.
8. **Tool isolation.** `check`, `fmt`, `build` with its link step, `outline`, `symbol`, `parse`, the compile steps of `run` and `test`, the checks of `repl`, the analyses of `lsp`, and the package operations run in workers: Landlock and seccomp on Linux, Seatbelt and a watched footprint on macOS, an AppContainer and a Job Object on Windows; limits from the `[compile]` table of the policy or 2 GiB and 10 minutes, a `compile.memory_bytes` below 192 MiB refused with 103 (RFC 0006); every worker ends with its whole process tree. Remaining: `stat` is not restricted, so a worker learns whether a path exists; the minimum of 192 MiB is measured on Linux x86-64 only; the tool reads the manifest and the policy itself to set up `run` and `test`; no `target/` is written (the temporary directory is used); `unio doc` does not exist.
9. **C-13 and reference counting.** Decided by RFC 0007 (closure condition 3 met): reference counting, freeing recursing at most 128 levels and draining deeper levels in a loop; the pause is gated on Lx64 (E1). Every value that holds values is freed this way, the captures of closures and the value of a resource included (a chain of closures each capturing the one before overflowed the native stack at 8 to 10 million closures, found by a probe on `9ba5d43` and fixed after it). Remaining: the tests of that fix have not run in CI (open item C-13); `==` compares and a key of a map or set is hashed by recursion, so a deep enough value overflows the native stack there (open item L-17a, C-18).
10. **Reproducibility.** Two builds of one source, also in two directories with another home, give the same bytes (`tests/native.rs`), and each executable records its linker and SDK (`unio build --print-toolchain`); the Rust toolchain, the crates, the runner images, linkers, and SDKs are pinned (release condition 3, `.github/scripts/expected_toolchain.py`). The job `reproducible` compares a second build on a second runner with the job `release` on every platform where 0.1 ships and looks for paths of the build machine; on Windows `unio.exe` is linked with `/Brepro` (`tests/release_build.rs`). It passed on Lx64 in E3 and has not run on the four platforms (rows R-6, O-1).
11. **Native targets.** `unio build` makes executables for the machine it runs on (no cross-compilation); code generation for all four targets is checked on every machine (`native::tests`). By the criterion of plan section 12 step 6: Win done (E1, with its AppContainer), Lx64 and La64 done (E2), mac pending (row C-5).
12. **Signing and trust.** Signed publishing, verification before extraction, the operator's trust anchors, rotation, revocation, expiry, and rollback protection with ML-DSA-65 for registries, and signed release manifests ([cryptography.md](cryptography.md) section 7, [packages.md](packages.md) section 7); `tests/packages.rs` passed on all four platforms in E1, `tests/signatures.rs` on Win in E1. Not in 0.1 by decision: TLS (downloads are not private). Missing, so that no component claims post-quantum compliance (R-6c): a signed time of indexes, an independent security review, fuzzing of the parsers, a review of the timing; and a release signed with the operator's key (O-5).
13. **File guarantees after power loss.** Fault injection fails `fsync`, `close`, `rename`, and the directory sync in turn; `tests/power_loss.rs` replays the recorded operations of real runs at every crash point on a model file system and kills programs, and on Linux the writer, at random points. Not done: a real power cut, dm-log-writes replay, powering off virtual machines (S-9b, C-19).
14. **Fuzzing.** `tests/fuzz.rs` runs 2,000 deterministic mutations and every reproducer; the coverage-guided fuzzer `compiler/unio/fuzz/` has six targets, and `fuzz.yml` runs it in five stages of 300 minutes with the job `evidence`. Remaining: the 24-hour run on the release commit (O-3).
