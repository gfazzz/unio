# Language and library contracts from the comparative review

Version: 0.1. Status: normative design for release 0.1, with explicitly scheduled later work. Accepted through [RFC 0001](rfcs/0001-language-contracts.md). Russian localization: [ru/language-contracts.md](ru/language-contracts.md). Requirements and the [plan](plan.md) define the release gates. Library sources are the normative API; declarations marked `external` still require runtime implementation.

## 1. Evaluation, parameters and exclusive access

**L-27.** Evaluate the receiver, operands and explicitly supplied arguments once, left to right in source order. A named argument does not reorder evaluation into declaration order. Evaluate only the selected branch of a conditional, the required operand of `and`/`or`, and the fallback of `Option or value` when absent. A `?.` chain skips subsequent member access and call arguments after `none`. An error/fault prevents later evaluations.

Resolve an assignment's destination, including its index expressions, before its right-hand side; assign only after the right-hand side succeeds. Resolution itself performs its bounds/access checks. Re-evaluating the destination is forbidden. Reject a right-hand side that mutates the destination's root while that destination is reserved; an explicit temporary expresses the intended order.

Defaults are evaluated afresh on each call, after explicit arguments, in parameter declaration order. They may refer to earlier immutable value parameters and module constants, but not `self`, `var` parameters or later parameters. Default expressions may allocate; they may not fail, acquire a resource or have OS effects. Their allocation effects contribute to the call. This avoids shared mutable defaults and effects hidden in omitted arguments.

**L-28.** `named` requires a label at the call. Ordinary parameters precede named-only ones; defaults trail within each group. A named-only parameter is a value parameter in 0.1. Function shapes preserve required labels and their order, with no defaults; default arguments belong only to direct calls of declarations. Labels are part of public API and compatibility checks. `named` remains an ordinary identifier outside modifier positions.

**L-29.** A mutable place consists of a root and field/index projections. Exclusive mutable access starts at invocation and ends on return, error or fault. Evaluate ordinary value arguments as snapshots before invocation, so `items.append(items.length())` is valid. Two mutable arguments (including `var self`) with the same root are rejected conservatively, even for different indices/fields. A simultaneous live resource read and mutation of that resource is also rejected; resource arguments cannot be copied into snapshots. No nested argument evaluation may invalidate a previously resolved mutable destination. Value captures in lambdas do not acquire mutable aliases. The restriction is checked statically, without lifetimes in signatures.

Acceptance: traces of nested calls, skipped branches/defaults and failing arguments; receiver plus argument conflicts, nested fields/indices and allowed value snapshots; interpreter/native agreement.

## 2. Significant results, interface ownership and numeric laws

**L-30.** A discarded `Result` or `std.process.Output` is a compile error, including a local binding that is never read. `let _ = expression` explicitly discards it. Other return values keep their current behavior. Reading a result is not proof of correct handling; process callers must still interpret `status`. Future task results follow the same rule. No general attribute system is introduced.

**L-31.** An interface implementation belongs to the package defining either the nominal outer type or the interface. A generic type parameter alone is not a locally owned type. Two potentially overlapping implementations are rejected, including blanket/concrete overlaps; there is no specialization priority. The standard library is one owning package across `core`/`alloc`/`std`; providing different methods in different layers is permitted, but each interface method has one implementation. Built-in implementations participate in this check. Generic bodies are checked against declared constraints, not accidental methods of one instantiation.

**L-32.** `Order` is total, transitive and antisymmetric; comparison equal to zero agrees with `Equal`. For hashable types, equality is an equivalence relation and equal values have equal hashes; hash/equality behavior of a stored key must not change. A `sorted_with` predicate must define a strict weak order. Sampled property tests check examples of these laws without proving them universally.

IEEE `Float` implements `Equal` with its documented nonreflexive NaN exception, has intrinsic partial comparisons, and implements neither `Order` nor `Hash`. Unordered comparisons are false; `NaN != NaN` remains true. `Float.total_order()` returns `OrderedFloat`: numeric order including infinities, both signed zeros equal, all NaN encodings equal and after positive infinity. For non-NaNs the key is the binary64 bit magnitude with the sign bit cleared, negated for negative inputs; zeros map to 0 and NaNs to MAXIMUM_INT. Its private canonical integer key supplies consistent `Equal`, `Order` and `Hash`. This is a deliberate canonical ordering, not a claim of bit-for-bit IEEE `totalOrder`. Use `values.sorted_by(function (x as Float) returns OrderedFloat: x.total_order())`. Runtime tests must include NaN payloads, infinities and both zeros.

## 3. Collections, callbacks and streaming

**S-13.** `sorted_by` computes each key exactly once, in input order, including a singleton. It is stable and uses O(n) additional key storage. `map`, `filter`, `fold`, `partition` and `group_by` visit elements in input order. `group_by` preserves first-occurrence order of keys and input order within groups. `fold` uses an explicit initial value. `zip` returns `none` on different lengths. `chunks` includes a short final block; `windows` includes only complete overlapping windows. Both return `none` for nonpositive sizes. These APIs are eager and return values, not delayed computations.

**S-14.** `try_map`, `try_filter`, `try_fold` propagate the callback's concrete error type and stop at its first failure without returning a partial collection. A callback with several errors uses an explicit named error adapter; no error-set polymorphism is added. Effects flow through function values and interface calls; a compiler must conservatively include all possible effects rather than treating an unknown callback as pure. This does not weaken declared permissions or the `core` layer check.

**S-15.** `range(start, end)` is a constant-space `Range` in `core`, empty when start >= end. A fresh `iterator()` returns an independent cursor implementing `Iterator[T].next(var self) -> Option[T]`; exhaustion is permanent. `for` and comprehensions create one cursor for their source and advance it once per iteration; `break` stops advancement. `List.iterator` traverses a value snapshot. A cursor is single-pass, a Range/List is repeatable. `.to_list()` explicitly materializes a range in `alloc`. Existing Text/Map/Set traversals retain their documented order. No count is computed by subtracting extreme range endpoints.

**S-16.** `files.open_reader` creates a resource in `using`. `read_bytes(max_bytes = ...)` returns a nonempty bounded chunk or `none` at EOF, never an empty chunk to signal temporary lack of progress. Return already buffered bytes before reporting a pending error on the next call; after an error subsequent calls report it. Nonpositive limits fail with `IoError.InvalidData`. A stream does not escape `using`; leaving that scope, including a return or error, releases it once. A `break` within a still-active `using` stops reading but keeps the resource open until that scope ends. EOF does not itself release the resource.

Stage 3/5 tests read a file larger than the memory budget, stop early, inject errors after partial reads and check descriptor release. A future text-stream adapter retains split UTF-8 sequences across chunks and reports invalid UTF-8 explicitly. General generator syntax and lazy combinators require a later RFC; explicit cursors and bounded byte reads meet the immediate need.

## 4. Data boundaries, Unicode and paths

**S-17.** Automatic JSON conversion is available only for supported scalar/container types and structs whose fields are all public and whose nested fields are themselves convertible. It never constructs or extracts private fields, even when called from the defining module. Decode a public transport type, then call the domain type's validating constructor. Missing fields with defaults use fresh defaults; absent required fields fail, including an `Option` field without a default. `null` is accepted only by `Option` or `Value`; it differs from absence. Unknown fields and unknown enum variants fail. Numeric conversion must not silently round or truncate; `Value.Float` to `Int` is rejected. Error paths use JSON Pointer escaping.

The parser rejects duplicate decoded keys, including differently escaped spellings. Defaults: at most 16 MiB of input UTF-8 and depth 128 (values on the root-to-leaf path, root depth 1); explicit positive named limits may override them under the process memory policy. Input-byte checks precede allocation of the scalar list. Limits bound input, not a promise of byte-for-byte heap usage. `encode_checked` rejects non-finite floats with an escaped JSON Pointer. The preexisting `encode` retains its documented conversion to `null`; configuration/protocol examples must use the strict API where fidelity matters.

**S-18.** Text is valid UTF-8. Length, positions, slices and `chars` count Unicode scalar values, excluding surrogate code points, not grapheme clusters. Equality, order and hashing use the exact scalar sequence without implicit normalization; canonically equivalent spellings may differ. A scalar offset index costs O(n) time and space to construct; indexed access/slicing are O(1) afterward. Slices may retain the backing storage. Grapheme segmentation and NFC/NFD normalization are explicit stage-5 Unicode APIs using a pinned Unicode data version; case conversion is locale-independent and may change length. Tests include composed/decomposed accents, family emoji, casing and chunk-split UTF-8.

**S-19.** `Path.normalize` is lexical: remove `.` and redundant separators, retain `..` because a preceding component may be a link. Preserve root, drive and UNC-share identity; Windows drive-relative `C:foo` is not absolute. `files.resolve` accesses the filesystem and may fail; it is not authorization and does not eliminate races before opening. Sandbox/path-relative descriptor operations enforce access at use. Cross-platform tests cover POSIX, Windows drives, rooted-relative paths, UNC shares and symlinks.

**S-20.** Errors expose a stable, fully qualified `diagnostic_code`, generated alongside `to_text`. `std.errors.ContextError` preserves an operation and an `Error` cause; code can inspect the cause's stable code without parsing localized prose. Handle concrete errors before wrapping when recovery depends on their fields. No dynamic downcast is added. Public context is an API contract; credentials/payloads are not inserted automatically. Structured diagnostic serialization must retain codes and context and redact data according to the caller's explicit policy.

## 5. Testing and interactive tools

**T-12.** `std.test.check_property` has deterministic generation, bounded shrinking and a replayable counterexample: scheme version `unio-property-v1`, seed, case index, sample seed, original/minimized value and shrink attempts. Generated seeds use the documented fixed integer algorithm in the source. Record compiler/library versions when storing a replay artifact. A minimized result is local to the shrinker and budget. Pure generators/predicates are required for replay. Test runners enforce time/memory limits even when a user generator hangs. Clock, random and I/O dependencies of tested applications are explicit injectable interfaces; test substitution does not mutate global runtime state. Stage 3 executes library properties; stage 5 integrates JSON replay and fault injection.

**T-13.** After the interpreter exists, `unio repl` uses the same type/error/resource checks and permissions as normal programs. Compilation stays in its nonexecuting worker; evaluation happens in a separate isolated runtime worker with explicit limits; inspection/type queries do not execute code. A resource cannot persist beyond a submitted `using` scope. Runtime errors may have completed external effects and are not described as transactional rollback. Documentation examples become executable tests. IDE incomplete-code diagnostics carry expected types and source revisions; applying a fix requires the matching revision and rerunning checks. No executable typed-hole syntax is added.

Nominal domain wrappers use existing structs with private fields and validating constructors. The guide includes identifiers, byte counts/durations and a validated port example. Physical-unit algebra and multi-statement lambdas remain evidence-gated follow-ups rather than new syntax in 0.1.

## 6. Packages, compatibility and cache identity

**T-14.** Imports `std.*` name the standard library, `deps.<alias>.<module>` name a manifest dependency, and other names stay package-relative. `deps` is reserved as a module root, not a keyword. An alias maps to a canonical registry origin plus owner/name; lock entries bind exact version, payload digest, signature/trust metadata and transitive edges. Types include that resolved package identity and module path. Two origins with the same display name do not share type identity. Release 0.1 allows one version per canonical package identity; incompatible major-version constraints fail with the dependency paths instead of creating two hidden copies.

Installation uses exact lock entries, validates target/runtime requirements, and never updates the lock silently. Offline build fails on missing/mismatched cache entries. `update` alone resolves requested changes against a recorded registry snapshot: deterministic backtracking over sorted package identities, trying satisfying stable versions in descending semantic-version order and respecting unchanged locked entries unless they are in the explicitly requested update set. An unsatisfiable frozen entry produces an explanation and an explicit broader-update suggestion, not a silent unlock. Prereleases require an explicit prerelease constraint. No install/build scripts run. Test diamonds, aliases, incompatible majors, origin substitution and offline failure. This refines the package-manager plan; no resolver exists yet.

**C-11b.** Distinguish source-symbol hash, artifact-cache key and test-result-cache key. Source hashing uses a versioned canonical representation, domain separation and SHA-384. For recursive declarations, compute strongly connected components; sort members by qualified identity, encode internal edges by identity and external edges by already computed dependency hashes, then hash the component. A member hash includes that component hash and the member's identity. This terminates for mutual recursion and is invariant under source declaration reordering. Names remain significant as in C-11a.

Artifact keys additionally bind compiler/backend/runtime/stdlib versions and digests, target and ABI, profile, flags, dependency lock and manifest permissions. Build inputs include the canonical source and toolchain configuration, not wall-clock time or implicit environment. Test keys additionally bind runner and generator versions, seeds, policy and declared input snapshots. Tests using an unrecorded file, environment, clock, randomness, network or process result are not reused. A source hash alone is never sufficient for artifact/test reuse. Test recursion, target/toolchain changes and external-input changes.

**T-15.** Package API comparison records exported types, parameter labels/defaults, error sets, constraints, enum variants and required permissions. Adding an enum variant can break exhaustive callers; renaming a named argument or widening an error set is a compatibility change. Tooling reports the affected callers and a migration when one is unambiguous. Hash changes alone are not an API-compatibility verdict.

## 7. Scheduled contracts after 0.1

These are accepted requirements for the corresponding future specifications, not additions to the 0.1 runtime.

- **0.2 Server:** tasks form owned scopes. Scope exit waits for children; first unhandled child failure requests sibling cancellation, waits for cleanup and reports secondary failures deterministically by creation order. Cancellation is cooperative, with deadlines and acknowledgement distinct from an external effect being undone. Task handles must be used. Background services have an explicit supervisor owner. Bound active work and queue capacity; expose queue saturation, cancellation and cleanup state. Tests include failure, blocked I/O, full queues and exactly-once release. Cheap tasks/virtual threads are implementation options, never substitutes for these limits.
- **UniOS U-0/U-2/U-3:** supervisor trees have restart strategy, restart-rate budget/backoff, shutdown deadline, escalation, dependency order and machine-readable state. A service fault is observed at an isolated process boundary; an ordinary task is not memory isolation. Restarts do not imply idempotent external actions. Test crash loops, dependency failure, resource limits, disconnected administration and authorized recovery through local CLI and SSH.
- **0.2 database libraries:** bind data parameters separately from command text; identifiers use a separate validated representation. No SQL syntax or dependency is added to the core.
- **0.3 Compute:** typed high-level kernels and explicit buffer/backend layers, specialization within declared constraints, memory and synchronization costs in diagnostics. Investigate dimensional types with examples before an RFC; no open multiple dispatch or user-code execution at compile time.
- **0.5 System:** ABI/layout/size/alignment/atomic contracts and allocation/copy costs are explicit and cross-target tested, preserving the existing unsafe boundary.
